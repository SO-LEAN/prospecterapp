# api (Symfony 8.1)

@AGENTS.md

The generic Symfony guidance above is overridden by the project rules below when they differ.

## Role

A JSON API that exposes the use cases of `packages/core`, a resource server for the SPA (`apps/front`): the members sign in with a Cognito user pool, whose tokens the API checks and whose credentials it adapts (ADR 0052). No server-rendered page. Full contract: `openapi.json` (generated, do not edit) and Swagger UI on `https://api.local.prospecter.io/api/doc`.

## Project overrides

- No Doctrine, no migrations: the aggregates live in DynamoDB (ADR 0048), the tables are created by `bin/console app:tables:recreate` (`make db`, the tests recreate them); the user pool by `bin/console app:user-pool:recreate`.
- No Symfony CLI: run commands through `docker compose run --rm php ...` (see the root `CLAUDE.md`).
- No API Platform: plain controllers documented with NelmioApiDocBundle attributes.
- Services in YAML: the ports and the services of the hexagon are registered in `config/services.yaml`, the core being pure PHP without Symfony attributes.
- Messenger is synchronous: the command and event buses have no transport, handled within the request (ADR 0029, 0042).
- `Request::get()` no longer exists: use `$request->attributes`, `$request->query` or `$request->request`.

## Writing an endpoint

- One business intent per endpoint (ADR 0025), one invokable controller per endpoint, in the folder of its bounded context: `src/<Context>/Controller/<Intent>Controller.php` (`Prospecting/Controller/RelocateController`, ADR 0087); `src/Me` (the `/api/me` endpoints: membership, profile), `src/Dashboard` and `src/Contacts` (a contact, `GET /api/contacts/{id}` and the intents answering it, with the link to its timeline when Prospecting offers it, `ContactReader`; `GET /api/contacts` with the organizations of each contact, `GET /api/phone-numbers/{phoneNumber}`: who calls, ADR 0072, `GET /api/contacts/{id}/organizations`, `GET /api/organizations/{id}/contacts`, and the timeline of an organization, `/api/organizations/{id}/exchanges`, its persons named by PersonalData, `OrganizationTimelineReader`, ADR 0076: one batch call per context, narrowed to its exchanges to make conform by `/api/organizations/{id}/exchanges-to-make-conform`, ADR 0079) compose contexts. `src/PersonalData/Controller` serves the forgetting of a contact, `src/Prospecting/Controller` the exchanges with a contact (`/api/contacts/{id}/exchanges`, ADR 0074), `src/Exchanges` one exchange (`/api/exchanges/{id}`: its detail, the correction of its `facts` or of its `text` alone, ADR 0078, its erasure, its `attachments`: joined, downloaded by a link signed for a moment, removed, after the browser sent the file with the form of `POST /api/uploads`, ADR 0077; `ExchangeReader` names its interlocutor, the contact in PersonalData or the organization itself in Prospecting, and the members who noted, corrected and made it conform in PersonalData, under the person ids `ConsultMember` of Accounts gives them); a contact is collected with its `organizationIds` (ADR 0042). Extend `AbstractController`. A change dispatches its command on `Shared\CommandBus` (synchronous, refusals of the core thrown back as is), then answers with the fresh resource read by a query (`Prospecting\OrganizationReader`, `Me\MyAccountReader`, which composes Accounts and PersonalData): commands return nothing (ADR 0029). A command is flat (ADR 0035): the controller passes the fields of the input, the id of the new resource from `Shared\Identities` (UUID v7) and `executedAt` from the Symfony clock (ADR 0036).
- URLs are resource-oriented. `POST` creates a resource or adds an entity to an aggregate (`POST /api/organizations`, `POST .../logo`), `PATCH` changes one part of a resource exposed as a sub-resource (`PATCH /api/organizations/{id}/address`), `DELETE` removes one. No `PUT`. Ids are UUIDs: routes declare `requirements: ['id' => Requirement::UUID]`.
- Input: `#[MapRequestPayload]` / `#[MapQueryString]` with a `final readonly` DTO in `src/<Context>/Input` (constraints as attributes, `#[Assert\Valid]` on nested DTOs), shaped like the matching part of the resource (`AddressInput` like `AddressResource`); the controller passes its fields to the flat command (ADR 0035). Unknown fields are rejected with a 422 violation each (`serializer.default_context` in `config/packages/framework.yaml`), never ignored.
- Files: `#[MapUploadedFile]` then `new UploadedFileInfo($file)` (an `SplFileInfo` whose extension is guessed from the content), always on `POST` (PHP does not parse multipart bodies on `PATCH`).
- Output: every intent returns the fresh resource (`OrganizationResource`, `AccountResource`), a `final readonly` class of `src/<Context>/Resource` built by a presenter of `src/<Context>/Presenter` (`src/Me/AccountResourcePresenter` for my account; the dashboard reuses `OrganizationPagePresenter`) from the response of a query. A presenter is an object of the call, never injected (ADR 0085): it implements the output port of its query, the controller or the reader (`OrganizationReader`, `TimelineReader`, `ExchangeReader`, `MyAccountReader`, `ContactReader`, `OrganizationTimelineReader`) builds it with the services it needs and the answers read before, passes it to the query, then answers with its `resource`; the other answers are read with the presenters of the core keeping them (`KeptPersons`), and a stateless mapper is a factory (`TimelineResourceFactory`, `ContactInListResourceFactory`, and for the images `Shared\ImageResourceFactory`: `url`, `smallUrl` 96 px and `mediumUrl` 256 px wide, made on first request by the storage app, never enlarged; the front picks the size it displays). Inputs live in `src/<Context>/Input`; what several contexts use in `src/Shared/{Input,Resource}`.
- Document every endpoint: `#[OA\Tag]`, `#[OA\Get|Post|Patch|Delete]`(summary), one `#[OA\Response]` per status with `new Model(type: ...)`. Then run `make api-doc` to regenerate `openapi.json` and the front types; `tests/Api/OpenApiContractTest` fails `make test` while the committed `openapi.json` differs from the code.
- Roles: one `#[IsGranted('ROLE_PROSPECTOR')]` or `#[IsGranted('ROLE_USER')]` per controller (`ROLE_ADMIN` inherits both, and `ROLE_PERSONAL_DATA`: an administrator manages the personal data the core lets them read, `Member::readsPersonalData()`); the core does not check roles.
- Access to a resource of Prospecting (ADR 0081): the controller receives its read model, an `OrganizationSheet` or an `ExchangeDetail` resolved from the `id` of the route (`Prospecting\OrganizationResolver`, `Exchanges\ExchangeResolver`), and declares `#[IsGranted(OrganizationVoter::ACCESS, subject: 'organization')]` (or `ExchangeVoter::ACCESS`; `tests/Architecture/ResourcesAreReachedThroughTheirVoterTest` fails otherwise). The voter (`Security\AccountResourceVoter`) only refuses a resource of another account, a 404 named like the refusal of the core (`unknownOrganization`, by `Security\ApiAccessDeniedHandler`); an intention needing the right to manage personal data declares the role too, `#[IsGranted(User::PERSONAL_DATA)]` (403), `StopProspecting` only while the organization has contacts (`denyAccessUnlessGranted()`); the state is checked by the core (409). The core still checks a contact of the account and what PersonalData lets its reader do.
- Links: a resource carries `_links` (HAL, plus `method`), built by its presenter from the possible intents of the core response (`Shared\Links`), those of Prospecting shown only when the member holds the role their controller requires, declared beside the route in the table of the presenter (`Security\IntentLinks`, ADR 0081): the key of a link is absent when the intention is not possible now (`SKIP_NULL_VALUES` on `_links`, optional in the contract), and the call then fails. Document a new intention as a new link.
- Errors: a use case refuses with `UseCaseRefused`, which `Shared\UseCaseExceptionListener` turns into RFC 9457 `application/problem+json` by its `ErrorType`: `NotFound` 404, `NotPossibleInItsState` 409 (the link is missing), `NotAllowed` 403 (no right to manage personal data in PersonalData: search contacts by text, collect or forget a contact; download an attachment; the profile of a colleague; in Prospecting the voters refuse the rest first), `BusinessRuleViolated` 422 with `violations`; the problem and its violation carry the `reason` (the class of the refusal, `invalidPhoneNumber`) and its `context`, which the SPA words in French (ADR 0073); any other exception is a failure (500); missing tokens 401 (`Security\ApiAuthenticationEntryPoint`), missing role or right 403, a resource of another account 404 (`Security\ApiAccessDeniedHandler`).
- CORS (`config/packages/nelmio_cors.yaml`) lists the allowed methods: a new verb must be added there, or the browser's preflight fails, and in the CORS of the HTTP API of `docker/lambda/deploy.sh` (MiniStack answers the preflights of the Lambda mode from it). In dev only, both expose `X-Debug-Token` and `X-Debug-Token-Link` too, so that the front reads the profile of a call (`tests/Local/ProfilerTest` checks they agree). On AWS the allowed origin, `CORS_ALLOW_ORIGIN`, is made by its Terraform from the address of the front (ADR 0066, 0067).

## Authentication

See `docs/auth.md` at the repository root. The members sign in on Cognito (the SPA, by SRP); the API checks their tokens and keeps what they sign in with (ADR 0052).

- Firewall `api` (`^/api/`, stateless, `access_token` with `Security\AccessTokenHandler`): the JWT is checked with the published key its `kid` names (`SignIn\SigningKeys`, cached), its issuer, its client, `token_use=access` and its expiry (`app.token_clock`); its `username` is the member id, loaded by `Security\MemberProvider` into `App\Security\User`, received as `#[CurrentUser] User $user`; its ids go into every command and query; the voters decide the access to a resource of Prospecting (ADR 0081), PersonalData and Accounts the rest (ADR 0026).
- `src/SignIn`: the user pool known by name (`UserPool`, ids cached, `COGNITO_*` variables), what a member signs in with (`Credentials`: login email unique on the platform, password, through the admin calls of Cognito), `GET /api/user-pool` (public, where the SPA signs in) and `/api/me/sign-in`; `app:user-pool:recreate [--demo]`, `app:user:set-password`, `app:account:open` (an account and its founder, ADR 0064), `app:member:register` (a member in the account of an administrator, ADR 0075), on AWS through `make console`.
- The members of the demonstration sign in with `Demo\DemoCredentials` under the member ids `DemoData::PROSPECTOR` and `DemoData::ASSISTANT`.

The delivery (controllers, inputs, resources, presenters, readers, security) uses the requests and responses of the application only; only the adapters of the ports use the domain (`tests/Architecture/DomainBehindTheApplicationTest`, ADR 0035). A context of the API uses nothing of another one but its Contract (`<Context>/Contract` of the core: published queries and integration events, `tests/Architecture/BoundedContextsTest`, ADR 0045, 0047). Security reads who calls with the query `ConsultMyAccount` (identities and roles, ADR 0040). Repositories answer the questions of the domain (`isEmailUsed()`) and decide nothing; the reservation of the email written with the aggregate (below) is the safety net of `EmailUniqueness` when two requests take the same email at once (ADR 0039, 0048). `tests/Architecture/BoundedContextsTest` fails when a context folder uses anything of another context but its Contract, the anticorruption adapters included.

The adapters of a context are grouped by kind: its repositories in `src/<Context>/Persistence`, the anticorruption layers of its ports to the other contexts in `src/<Context>/AntiCorruption` (ADR 0086). Ports are aliased to adapters in `config/services.yaml`. Every `*Handler` of the core is a service; those implementing `Prospecter\Core\SharedKernel\Application\CommandHandler` are registered on `command.bus` through `RefusalTranslatingHandler` by `Shared\DependencyInjection\RefusalTranslatingHandlersPass`; the same pass wraps every `QueryHandler` and aliases it by the name of its intent, so a class calling one asks for `RefusalTranslatingHandler $consultOrganization` (`ConsultOrganizationHandler`) (ADR 0035, 0044). Nothing is built in a constructor and no service by the code: everything is injected (`make lint` checks it, ADR 0044); the services of the hexagon are registered in `config/services.yaml` (`config/packages/messenger.yaml`: no transport, handled in the request). Those implementing `EventHandler` are tagged on `event.bus` (synchronous, `allow_no_handlers`), routed by the type of the event they take: a domain event of their context (the `Publish…` translators) or an integration event of another context (ADR 0042, 0046). `bin/console debug:messenger` (`make commands`) lists both buses.

Each bounded context has its own DynamoDB table (ADR 0038, 0048): `<DYNAMODB_TABLE_PREFIX>-<context>` (`prospecter-dev-prospecting`; the prefix `prospecter-test` in tests), a `Shared\Persistence\Table` injected by name in the persistence of its context only (`Table $prospectingTable`); `tests/Architecture/TablePerContextTest` fails otherwise. Nothing spans two contexts. Locally the tables live in MiniStack (`ministack` service of `docker-compose.yml`, `DYNAMODB_ENDPOINT`, dev credentials in `.env`); `Shared\Persistence\Tables` creates them all alike (`PK`/`SK`, the indexes `GSI1` and `GSI2`, and `NAME`, `EMAIL` and `PHONE` finding an aggregate, billed by request; on AWS `infra/tables.tf`, alike), `make db` with the data of the demonstration (`Demo\DemoData`, written through the domain and publishing its events like a use case).

- Single-table design, each repository documenting its items: `ORGANIZATION#<id>` listed by account in `GSI1` and by holding in `GSI2`, the links `CONTACT#<person>` / `ORGANIZATION#<id>`; `EXCHANGE#<id>` in the timeline of its contact in `GSI1` (`TIMELINE#<account>#<person>`, by its moment then its id, ADR 0074), the links `EXCHANGES#<organization>` / `EXCHANGE#<id>`, in the timeline of the organization in `GSI1` (`ORGANIZATION_TIMELINE#<organization>`, ADR 0076) and, while their exchange is to make conform, in `GSI2` (`TO_MAKE_CONFORM#<organization>`, counted there, ADR 0079); `PERSON#<id>` listed by account and purpose; `ACCOUNT#<id>`, `MEMBER#<id>`; the journal `JOURNAL#<subject>` (ADR 0043).
- An aggregate is stored as a plain document (`OrganizationDocument`, `PersonDocument`, `Shared\Persistence\Documents` for the value objects of the shared kernel, moments in UTC to the microsecond) and restored without its constructor by `Shared\Persistence\Hydrator`: the domain keeps its value objects and private properties (ADR 0028); a new property of an aggregate or a value object needs a change of its document.
- `save()` writes in one transaction the aggregate and what follows from it: the reservation of its email (`EMAIL#...`, written under a condition, so that a second holder cancels the transaction into `EmailAlreadyUsed`, the safety net of `EmailUniqueness`, ADR 0039), the links of its contacts.
- Lists come in slices newest first after a cursor (ADR 0049); a search finds an aggregate by the beginning of its name or of its email (ADR 0071): its item carries its search keys as the keys of the indexes `NAME` and `EMAIL`, and its phone number in E.164 as the key of `PHONE` (ADR 0072) (`Shared\Persistence\SearchIndexes`, keys only), written with it; `bin/console app:search:rebuild` writes them again for every aggregate and removes the items of the former search (ADR 0050).

## Hosts

- `APP_API_HOST` (`api.local.prospecter.io`), routes in `src/{Me,Prospecting,PersonalData,SignIn,Dashboard,Contacts,Exchanges}/Controller` (`config/routes.yaml`), and `src/Doc` (`/favicon.ico`, `config/routes/nelmio_api_doc.yaml`; `VersionedNelmioAssets` asks the files of Swagger UI on the CDN at the installed version of NelmioApiDocBundle); locally nginx passes `/cognito/` of the same host to the Cognito of MiniStack, for the SPA.
- The API runs in a Lambda with the Bref layer (FPM runtime, `bref/bref`) behind an HTTP API of MiniStack, the repository mounted in the dev environment (ADR 0053, 0055; `make start`): `php/conf.d/bref.ini` enables the extensions the layer ships disabled (`intl`; a new extension the API needs goes there too), `TRUSTED_PROXIES` (`REMOTE_ADDR` in the function, empty for the tests) lets Symfony trust the `X-Forwarded-Proto` of the gateway. The functions write the cache and the logs of dev in the repository, PHP-FPM serving as its owner (`docker/lambda/bootstrap`); the profiler of dev keeps its profiles in `var/profiler`, out of the cache, so that a `cache:clear` (`make db`) keeps the history: read it on https://api.local.prospecter.io/_profiler, or from the `X-Debug-Token-Link` of a response in the network panel; `make profiler-clear` empties it. The tests run on the command line of the `php` container.
- On AWS (`infra/`, ADR 0063, 0067, 0068): the function runs `build/api.zip` (`make package-api`, `make/lambda.mk`), read-only (`Kernel` extends `BrefKernel`), behind its HTTP API on the domain of the edge, its `execute-api` address closed; `Shared\OnlyThroughTheEdge` refuses a request without the secret of the edge (`ORIGIN_SECRET`, header `X-Origin-Verify`), and every secret is read in SSM at the start (`bref-ssm:`).
- Files are not the API's business: the storage app (`apps/storage`, `static.local.prospecter.io`) keeps and serves them, and `Shared\ImageResourceFactory` names their sizes by its convention (`<public url>/<size>/<path>`, ADR 0033).

## Tests

- `tests/Api`: functional tests through `Base/ApiTestCase`, whose `login()` signs a member in for real on the user pool `prospecter-test` of MiniStack (`AccessTokenTest`, `SignInTest`). The tables of the prefix `prospecter-test` and the user pool are recreated for each test, in MiniStack (`make test-api` starts it), with the data and the members of the demonstration; host `api.test.prospecter.io`; variables in `.env.test`.
- `tests/<Context>`: the adapters on their real table or service (`DynamoPersonRepositoryTest`: the reservation refuses an email taken meanwhile; `OrganizationSearchTest`: found by the beginning of the name or of the email, the keys written again; `GeoplateformeGeoLocationTest`; `SignIn/RsaPublicKeyTest`); `tests/Architecture`: the boundaries (contexts, domain behind the application, one table per context); `tests/Local`: what only the local stack has (the profiler, its CORS). A test failing because of a limit of MiniStack is skipped with its reason; a dev instance on AWS is the safety net.
- Unit tests extend PHPUnit's `TestCase` and use hand-written doubles (`tests/Double`), no mock library.
- PHPUnit 13: attributes only (`#[DataProvider]`, `#[Group]`), static data providers, abstract base classes named `*TestCase`.
