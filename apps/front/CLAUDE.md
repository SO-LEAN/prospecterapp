# front (React SPA)

## What is in force

Read before working on it: `docs/architecture/front.md` (stack, folders, state, data flow, navigation, API access, and its rules), `docs/architecture/design-system.md` (design rules), `docs/architecture/auth.md` (sign-in on Cognito by SRP).

## Commands

Run through Docker from the repository root (no Node on the host): `docker compose run --rm --no-deps node pnpm <script>`, or the Makefile (`make test-front`, `make lint`, `make fix`, `make e2e`, `make api-doc`). The dev server runs in the `node` service (`make start`) behind https://local.prospecter.io.

Scripts: `dev`, `build`, `preview`, `typecheck` (tsc 7), `lint` / `format` (Biome), `test` / `test:watch` (Vitest), `e2e` (Playwright, use `make e2e`: its global setup `e2e/wait-for-the-stack.ts` waits for the stack to answer), `api:types`.

Before declaring work done: `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `make e2e` for changes to a main journey.

## Gotchas

- The configuration (`shared/config/env.ts`) comes from `window.prospecter`, set by `/config.js` (empty locally, `public/config.js`; on AWS answered by the CloudFront Function of the instance, ADR 0066), else from the `VITE_*` variables of the build: a new setting goes in both.

- TypeScript 7 is the native compiler and has no JavaScript compiler API: tools that need it (openapi-typescript) run with `pnpm dlx` and their own TypeScript 5 (see the `api:types` script).
- pnpm 12 ignores the `pnpm` field of `package.json` (settings would go in a `pnpm-workspace.yaml`, none is needed today); the store is set by `npm_config_store_dir` in the node image and lives in the `pnpm-store` Docker volume.
- The sign-in screen (`routes/auth/sign-in.tsx`, ADR 0037, 0052) is outside the app shell: the `_app` guard sends an anonymous visitor there with `returnTo`, a path of the SPA only (`shared/auth/sign-in-page.ts`), opened once signed in.
- `amazon-cognito-identity-js` reads the Node `global`: `vite.config.ts` defines it as `globalThis` (without it the page stays blank, "global is not defined").
- `routeTree.gen.ts` is generated by the router plugin on `vite`/`vite build`; commit it, do not edit it.
- shadcn's generator may write `import { cn } from "cn"`: replace with `@/shared/lib/utils`. Its sonner wrapper expects `next-themes`: ours uses `useResolvedTheme`. Do not keep the `cn` or `next-themes` packages it installs.
- Self-signed certificate: the browser must accept it once per host (SPA, API, static).
- The e2e journeys run one at a time (`workers: 1`): they sign the same demonstration member in, and signing out is a Cognito global sign-out, which would sign out the journeys running beside.
- `make e2e` runs Playwright in the network of the stack (`prospecterapp_default`), the local hosts resolved to the address of `pro-nginx` there, never on the network of the host: each container a function starts there changes its interfaces, and Chromium drops its requests (`net::ERR_NETWORK_CHANGED`), the first journey after a switch of the stack failing (ADR 0084).
- MapLibre 6 loads its worker from `maplibre-gl-worker.mjs` next to its own file, which Vite bundling moves: `map-view.tsx` passes the real URL (`?url` import + `setWorkerUrl`). Without it the map stays grey (markers shown, no tiles, "Worker failed to load" in the console).
- The stylesheet of MapLibre comes with the lazy chunk of the map, after `app/styles.css`: a rule restyling its elements (the popups) goes in `shared/ui/map/map-view.css`, imported right after it, or MapLibre wins at equal specificity (a white popup in the dark theme).
