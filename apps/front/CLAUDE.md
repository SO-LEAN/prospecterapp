# front (React SPA)

Architecture and the reasons behind each choice: `docs/front-architecture.md`. Design rules: `docs/design-system.md`. OAuth flow: `docs/auth.md`.

## Commands

Run through Docker from the repository root (no Node on the host): `docker compose run --rm --no-deps node pnpm <script>`, or the Makefile (`make test-front`, `make lint`, `make fix`, `make e2e`, `make api-doc`). The dev server runs in the `node` service (`make start`) behind https://local.prospecter.io.

Scripts: `dev`, `build`, `preview`, `typecheck` (tsc 7), `lint` / `format` (Biome), `test` / `test:watch` (Vitest), `e2e` (Playwright, use `make e2e`), `api:types`.

Before declaring work done: `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `make e2e` for changes to a main journey.

## Rules

- Respect the folders: `routes/` thin (loader + page), `features/<feature>/` (queries, mutations, schema, components), `shared/` business agnostic. A feature never imports another feature; shared query keys go to `shared/api/keys.ts`. `shared` imports nothing from `app`, `features` or `routes` (Biome `noRestrictedImports` refuses it).
- Server data only through TanStack Query with the generated clients (`api` for the API, `authApi` for `/auth/me`, `signInApi` for the sign-in only: it sends the session cookie of the authorization server and no token). Never `fetch` by hand, never copy server data into `useState` or Zustand. Mutations update the cache with the returned resource, then invalidate the affected list prefixes.
- Route data: `loader` with `context.queryClient.ensureQueryData(...)`, page with `useSuspenseQuery`, plus `pendingComponent` and `errorComponent`. Search state in validated search params; a list comes in slices (`useInfiniteQuery`, the link `next`, "Charger plus", ADR 0049), never numbered pages.
- Never write `useMemo`/`useCallback`/`memo` for performance: the React Compiler does it.
- After an API change: `make api-doc` (regenerates `src/shared/api/schema.d.ts` for the API and `auth-schema.d.ts` for the authorization server, never edited by hand) and fix the type errors. `api` calls the API, `authApi` what a member signs in with (`/auth/me`).
- Forms: react-hook-form + zod schema mirroring the API constraints; show server violations with `applyViolations`. A resource is changed section by section, one intent each: `EditableSection` + `SectionForm`, shared field groups in `shared/forms`, fields through `FormField` (it subscribes to its own error; the React Compiler would not re-render a memoized group). Only a creation has a full form. Show an action only when the resource carries its link (`_links.<intention>`), never from the data itself.
- UI: compose `shared/ui` components and semantic tokens (`bg-card`, `text-muted-foreground`…), no raw colors, no inline styles. Every text through `t()` with a key added to `shared/i18n/fr.ts` (keys are typed).
- Navigation: "Retour" goes back in history (`shared/ui/back-button.tsx`, fallback link when opened directly), a creation form is left with `useGoBack` and replaces itself (`replace: true`), so going back never lands on a form already submitted or cancelled.
- Accessibility: every control labelled (`Field`), icons `aria-hidden` next to text, keyboard reachable.
- Style: Biome (single quotes, no semicolons, 110 columns), `import type` for types, `@/` alias for `src/`.

## Gotchas

- TypeScript 7 is the native compiler and has no JavaScript compiler API: tools that need it (openapi-typescript) run with `pnpm dlx` and their own TypeScript 5 (see the `api:types` script).
- pnpm 12 ignores the `pnpm` field of `package.json` (settings would go in a `pnpm-workspace.yaml`, none is needed today); the store is set by `npm_config_store_dir` in the node image and lives in the `pnpm-store` Docker volume.
- The `_app` guard reads `userManager.getUser()`: the `useAuth()` state is not up to date in the same tick as the OAuth callback navigation.
- The sign-in screen (`routes/auth/sign-in.tsx`, ADR 0037) is outside the app shell: the authorization server sends an anonymous `/authorize` there, and the screen opens it again once signed in (`resume`).
- `routeTree.gen.ts` is generated by the router plugin on `vite`/`vite build`; commit it, do not edit it.
- shadcn's generator may write `import { cn } from "cn"`: replace with `@/shared/lib/utils`. Its sonner wrapper expects `next-themes`: ours uses `useResolvedTheme`. Do not keep the `cn` or `next-themes` packages it installs.
- Self-signed certificate: the browser must accept it once per host (SPA, API, static).
- MapLibre 6 loads its worker from `maplibre-gl-worker.mjs` next to its own file, which Vite bundling moves: `map-view.tsx` passes the real URL (`?url` import + `setWorkerUrl`). Without it the map stays grey (markers shown, no tiles, "Worker failed to load" in the console).
