# auth (Symfony 8.1)

@AGENTS.md

The generic Symfony guidance above is overridden by the project rules below when they differ.

## Role

The authorization server of Prospecter (ADR 0034, flow in `docs/auth.md`): it signs members in and issues the OAuth 2 tokens the SPA calls the API with, and keeps what a member signs in with (login email, password). It knows a member by its id only: no dependency on the core, no business rule.

- Served on `api.local.prospecter.io` beside the API: nginx gives it `/authorize`, `/token`, `/login`, `/logout` and `/auth/*` (`docker/nginx/auth_fastcgi.conf`).
- `league/oauth2-server-bundle`: authorization code with PKCE for the public client `prospecter-front`, JWT access tokens 15 min whose subject is the member id, rotated refresh tokens 30 days. Keys in `config/jwt` (`make keys`, never committed); the API reads the public one.
- `Credentials` (table `credentials`), `LoginEmails` (unique on the platform), `Passwords`; `bin/console app:user:set-password <login email>`.
- No page of its own: the sign-in screen is in the SPA (ADR 0037), which posts the credentials to `POST /login` (`Security\SignInAuthenticator`: SPA origin only, throttled, answers the interrupted `/authorize` to open again); an anonymous `/authorize` is sent to `FRONT_URL/auth/sign-in`.
- `POST /login`, `GET /auth/me`, `PATCH /auth/me/login-email`, `PATCH /auth/me/password`: documented with Nelmio, contract `openapi.json` (generated by `make api-doc`, checked by `tests/OpenApiContractTest`), front types `apps/front/src/shared/api/auth-schema.d.ts`.
- Its own SQLite database (`var/data_<env>.db`), schema from the mapping, no migrations; `make db` recreates it with the OAuth client and the credentials of the prospector, under the member id of the API fixtures.

## Commands

From the repository root: `make test-auth`; `make lint`, `make fix`, `make api-doc` and `make db` cover it. One command: `docker compose run --rm --no-deps -w /var/www/src/apps/auth php <cmd>`.

## Tests

`tests/AuthTestCase`: the database recreated for each test with the fixtures, `signIn()` (session) and `signInWithAToken()` (the real authorization code flow with PKCE, then the bearer token). `SignInTest` signs in like the SPA, each test from an address of its own (failed attempts are counted per address and login email).
