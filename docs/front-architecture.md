# Front architecture (apps/front)

A React single page application talking to the API (`apps/api`) over JSON, signed in with OAuth 2.

## Stack and why

| Concern | Choice | Why |
|---|---|---|
| UI library | React 19 + React Compiler | The compiler memoizes components and hooks: no hand-written `useMemo`/`useCallback`. |
| Language | TypeScript 7 (native compiler), strict | Fast type checking; `noUncheckedIndexedAccess` catches undefined array access. |
| Build | Vite 8 | Instant dev server and HMR, Rolldown production build. |
| Routing | TanStack Router (file routes) | Fully typed links, params and search params; automatic code splitting per route; loaders. |
| Server state | TanStack Query | Cache, request deduplication, background refresh, targeted invalidation. |
| API client | openapi-fetch + openapi-react-query | Types generated from the API contract: a renamed field breaks the build, not production. |
| Client state | Zustand | Tiny store for UI preferences only (theme, sidebar). |
| Forms | react-hook-form + zod | Uncontrolled inputs (no re-render per key), schema validation mirroring the API. |
| Auth | oidc-client-ts + react-oidc-context | Standard OAuth 2 authorization code + PKCE, token refresh. |
| UI kit | shadcn/ui (Radix) + Tailwind CSS 4 | Accessible primitives, code owned by the project (see `design-system.md`). |
| Maps | MapLibre + OpenFreeMap | Open source vector maps, no API key; loaded lazily. |
| i18n | react-i18next, typed keys | French today, other languages without touching the screens. |
| Quality | Biome, Vitest + Testing Library, Playwright | One fast linter/formatter; component tests as a user would act; real end-to-end journeys. |

## Folders

```
src/
  main.tsx              entry: i18n, styles, <App/>
  app/                  wiring of the application
    providers.tsx       Auth, Query, Tooltip providers, toasts, router
    router.tsx          router instance and its context (queryClient, auth)
    query-client.ts     cache defaults and global error handling
    auth.ts             OAuth settings (UserManager)
    env.ts              typed VITE_* variables
    layout/             app shell: sidebar navigation, header, user menu
    styles.css          design tokens (Tailwind theme)
    routeTree.gen.ts    generated by the router plugin, do not edit
  routes/               one file per URL, thin: loader + page component
  features/<feature>/   business screens: queries.ts, mutations.ts, schema.ts, components/
  shared/               reusable, business-agnostic code
    api/                client.ts, schema.d.ts (generated), problem.ts, keys.ts, upload.ts
    ui/                 design system components (shadcn) + form/, feedback/, map/
    i18n/               setup and fr.ts
    lib/ hooks/ stores/ utilities, hooks, Zustand stores
  test/setup.ts         Vitest setup
e2e/                    Playwright journeys
```

Dependency rule: `shared` depends on nothing of the app; a `feature` depends only on `shared`; `routes` and `app` compose features. Query key prefixes used by several features live in `shared/api/keys.ts`.

## State: each kind in its place

| State | Where | Example |
|---|---|---|
| Server data | TanStack Query cache | organizations, my account, dashboard |
| URL | Router search params, validated by zod | `?q=acme&page=2` on the organizations list |
| UI preferences | Zustand, persisted in localStorage | theme, collapsed sidebar |
| Form | react-hook-form | the organization being edited |
| Session | oidc-client-ts (sessionStorage) | access and refresh tokens |
| Local UI | `useState` | a dialog being open |

Never copy server data into Zustand or `useState`: read it from the query, the cache is the single source of truth.

## Data flow and performance

- Queries are declared once as options (`organizationQuery(id)` in `features/*/queries.ts`) and reused by route loaders and components.
- Route loaders call `queryClient.ensureQueryData(...)`: the data is fetched before the page renders (no loading waterfall), and with `defaultPreload: 'intent'` hovering a link starts loading its code and data.
- Pages read with `useSuspenseQuery`: no undefined checks, the route `pendingComponent` shows a skeleton when loading takes time.
- `staleTime` 30 s: navigating back and forth does not refetch; data refreshes in the background when the window regains focus.
- Lists keep the previous page on screen while the next loads (`placeholderData: keepPreviousData`); the search input is debounced (300 ms) and written to the URL.
- Mutations put the returned resource directly in the cache (`setQueryData`), then invalidate only the lists that may change; invalidated queries refetch only if displayed.
- Code splitting: one chunk per route (router plugin), MapLibre loaded with `lazy()` only on pages with a map.

## API access

- `pnpm api:types` (or `make api-doc` from the root) regenerates `shared/api/schema.d.ts` from `apps/api/openapi.json`.
- `api.queryOptions('get', '/api/organizations/{id}', { params })` / `api.useMutation('put', ...)`: path, params, body and response are typed.
- The fetch middleware adds `Authorization: Bearer`; on a 401 it renews the token once with the refresh token, otherwise it sends the user to sign in.
- Form values have the shape of the API input (`address.city`, `organization.corporateName`), so the `propertyPath` of each API violation is the form field name.
- Errors are RFC 9457 problem details (`shared/api/problem.ts`): `applyViolations()` puts the server validation errors on the form fields; other mutation errors raise a toast (`query-client.ts`), unless the mutation sets `meta: { silentValidation: true }` and handles 422 in its form.
- Uploads are separate multipart endpoints (`shared/api/upload.ts`).

## Authentication

See `docs/auth.md`. In the SPA: `app/auth.ts` configures the client; the `_app` layout route guards every page by reading the stored session (`userManager.getUser()`), not the React auth state, which lags right after the OAuth callback.

## Adding a screen

1. If the API changed, `make api-doc`.
2. In `features/<feature>/`: query options, mutations (update the cache), zod schema mirroring the API input, components.
3. A route file in `routes/_app/...` with a `loader` (`ensureQueryData`), `pendingComponent`, `errorComponent`, and the page component.
4. Texts in `shared/i18n/fr.ts`.
5. A component test for the behaviour, and a Playwright step if it is a main journey.
