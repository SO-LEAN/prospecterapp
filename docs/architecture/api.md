# The API

What is in force; the reasons are in the records it names (`docs/adr`), read only to know why or before changing it (ADR 0090).

`apps/api`: a JSON API exposing the use cases of the core, a resource server for the SPA (ADR 0006, 0052). Its persistence: `persistence.md`; its authentication: `auth.md`; how it runs: `local-stack.md`, `infra.md`.

## Writing an endpoint

- One business intent per endpoint (ADR 0025), one invokable controller per endpoint, in the folder of its bounded context: `src/<Context>/Controller/<Intent>Controller.php` (`Prospecting/Controller/RelocateController`, ADR 0087); `src/Me` (the `/api/me` endpoints: membership, profile), `src/Dashboard` and `src/Contacts` (a contact, `GET /api/contacts/{id}` and the intents answering it, with the link to its timeline when Prospecting offers it, `ContactReader`; `GET /api/contacts` with the organizations of each contact, `GET /api/phone-numbers/{phoneNumber}`: who calls, ADR 0072, `GET /api/contacts/{id}/organizations`, `GET /api/organizations/{id}/contacts`, and the timeline of an organization, `/api/organizations/{id}/exchanges`, its persons named by PersonalData, `OrganizationTimelineReader`, ADR 0076: one batch call per context, narrowed to its exchanges to make conform by `/api/organizations/{id}/exchanges-to-make-conform`, ADR 0079) compose contexts. `src/PersonalData/Controller` serves the forgetting of a contact, `src/Prospecting/Controller` the exchanges with a contact (`/api/contacts/{id}/exchanges`, ADR 0074), `src/Exchanges` one exchange (`/api/exchanges/{id}`: its detail, the correction of its `facts` or of its `text` alone, ADR 0078, its erasure, its `attachments`: joined, downloaded by a link signed for a moment, removed, after the browser sent the file with the form of `POST /api/uploads`, ADR 0077; `ExchangeReader` names its interlocutor, the contact in PersonalData or the organization itself in Prospecting, and the members who noted, corrected and made it conform in PersonalData, under the person ids `ConsultMembersService` of Accounts gives them, asked once for all of them); a contact is collected with its `organizationIds` (ADR 0042). Extend `AbstractController`. A change dispatches its command on `Shared\CommandBus` (synchronous, refusals of the core thrown back as is), then answers with the fresh resource read by a query (`Prospecting\OrganizationReader`, `Me\MyAccountReader`, which composes Accounts and PersonalData): commands return nothing (ADR 0029). A command is flat (ADR 0035): the controller passes the fields of the input, the id of the new resource from `Shared\Identities` (UUID v7) and `executedAt` from the Symfony clock (ADR 0036).
- URLs are resource-oriented. `POST` creates a resource or adds an entity to an aggregate (`POST /api/organizations`, `POST .../logo`), `PATCH` changes one part of a resource exposed as a sub-resource (`PATCH /api/organizations/{id}/address`), `DELETE` removes one. No `PUT`. Ids are UUIDs: routes declare `requirements: ['id' => Requirement::UUID]`.
- Input: `#[MapRequestPayload]` / `#[MapQueryString]` with a `final readonly` DTO in `src/<Context>/Input` (constraints as attributes, `#[Assert\Valid]` on nested DTOs), shaped like the matching part of the resource (`AddressInput` like `AddressResource`); the controller passes its fields to the flat command (ADR 0035). Unknown fields are rejected with a 422 violation each (`serializer.default_context` in `config/packages/framework.yaml`), never ignored.
- Files: `#[MapUploadedFile]` then `new UploadedFileInfo($file)` (an `SplFileInfo` whose extension is guessed from the content), always on `POST` (PHP does not parse multipart bodies on `PATCH`).
- Output: every intent returns the fresh resource (`OrganizationResource`, `AccountResource`), a `final readonly` class of `src/<Context>/Resource` built by a presenter of `src/<Context>/Presenter` (`src/Me/AccountResourcePresenter` for my account; the dashboard reuses `OrganizationPagePresenter`) from the response of a query. A presenter is an object of the call, never injected (ADR 0085): it implements the output port of its query, the controller or the reader (`OrganizationReader`, `TimelineReader`, `ExchangeReader`, `MyAccountReader`, `ContactReader`, `OrganizationTimelineReader`) builds it with the services it needs and the answers read before, passes it to the query, then answers with its `resource`; the other answers are read with the presenters of the core keeping them (`KeptPersons`), and a stateless mapper is a factory (`TimelineResourceFactory`, `ContactInListResourceFactory`, and for the images `Shared\ImageResourceFactory`: `url`, `smallUrl` 96 px and `mediumUrl` 256 px wide, made on first request by the storage app, never enlarged; the front picks the size it displays). Inputs live in `src/<Context>/Input`; what several contexts use in `src/Shared/{Input,Resource}`.
- Document every endpoint: `#[OA\Tag]`, `#[OA\Get|Post|Patch|Delete]`(summary), one `#[OA\Response]` per status with `new Model(type: ...)`. Then run `make api-doc` to regenerate `openapi.json` and the front types; `tests/Api/OpenApiContractTest` fails `make test` while the committed `openapi.json` differs from the code.
- Roles: one `#[IsGranted('ROLE_PROSPECTOR')]` or `#[IsGranted('ROLE_USER')]` per controller (`ROLE_ADMIN` inherits both, and `ROLE_PERSONAL_DATA`: an administrator manages the personal data the core lets them read, `Member::readsPersonalData()`); the core does not check roles.
- Access to a resource of Prospecting (ADR 0081): the controller receives its read model, an `OrganizationSheet` or an `ExchangeDetail` resolved from the `id` of the route (`Prospecting\OrganizationResolver`, `Exchanges\ExchangeResolver`), and declares `#[IsGranted(OrganizationVoter::ACCESS, subject: 'organization')]` (or `ExchangeVoter::ACCESS`; `tests/Architecture/ResourcesAreReachedThroughTheirVoterTest` fails otherwise). The voter (`Security\AccountResourceVoter`) only refuses a resource of another account, a 404 named like the refusal of the core (`unknownOrganization`, by `Security\ApiAccessDeniedHandler`); an intention needing the right to manage personal data declares the role too, `#[IsGranted(User::PERSONAL_DATA)]` (403), `StopProspecting` only while the organization has contacts (`denyAccessUnlessGranted()`); the state is checked by the core (409). The core still checks a contact of the account and what PersonalData lets its reader do.
- Links: a resource carries `_links` (HAL, plus `method`), built by its presenter from the possible intents of the core response (`Shared\Links`), those of Prospecting shown only when the member holds the role their controller requires, declared beside the route in the table of the presenter (`Security\IntentLinks`, ADR 0081, 0088): the key of a link is absent when the intention is not possible now (`SKIP_NULL_VALUES` on `_links`, optional in the contract), and the call then fails. Document a new intention as a new link.
- Errors: a use case refuses with `UseCaseRefused`, which `Shared\UseCaseExceptionListener` turns into RFC 9457 `application/problem+json` by its `ErrorType`: `NotFound` 404, `NotPossibleInItsState` 409 (the link is missing), `NotAllowed` 403 (no right to manage personal data in PersonalData: search contacts by text, collect or forget a contact; download an attachment; the profile of a colleague; in Prospecting the voters refuse the rest first), `BusinessRuleViolated` 422 with `violations`; the problem and its violation carry the `reason` (the class of the refusal, `invalidPhoneNumber`) and its `context`, which the SPA words in French (ADR 0073); any other exception is a failure (500); missing tokens 401 (`Security\ApiAuthenticationEntryPoint`), missing role or right 403, a resource of another account 404 (`Security\ApiAccessDeniedHandler`).
- CORS (`config/packages/nelmio_cors.yaml`) lists the allowed methods: a new verb must be added there, or the browser's preflight fails, and in the CORS of the HTTP API of `docker/lambda/deploy.sh` (MiniStack answers the preflights of the Lambda mode from it). In dev only, both expose `X-Debug-Token` and `X-Debug-Token-Link` too, so that the front reads the profile of a call (`tests/Local/ProfilerTest` checks they agree). On AWS the allowed origin, `CORS_ALLOW_ORIGIN`, is made by its Terraform from the address of the front (ADR 0066, 0067).

## The delivery and the wiring

The delivery (controllers, inputs, resources, presenters, readers, security) uses the requests and responses of the application only; only the adapters of the ports use the domain (`tests/Architecture/DomainBehindTheApplicationTest`, ADR 0035). A context of the API uses nothing of another one but its Contract (`<Context>/Contract` of the core: published queries and integration events, `tests/Architecture/BoundedContextsTest`, ADR 0045, 0047). Security reads who calls with the query `ConsultMyAccount` (identities and roles, ADR 0040). Repositories answer the questions of the domain (`isEmailUsed()`) and decide nothing; the reservation of the email written with the aggregate (below) is the safety net of `EmailUniqueness` when two requests take the same email at once (ADR 0039, 0048). `tests/Architecture/BoundedContextsTest` fails when a context folder uses anything of another context but its Contract, the anticorruption adapters included.

The adapters of a context are grouped by kind: its repositories in `src/<Context>/Persistence`, the anticorruption layers of its ports to the other contexts in `src/<Context>/AntiCorruption` (ADR 0086). Ports are aliased to adapters in `config/services.yaml`. Every `*Handler` of the core is a service; those implementing `Prospecter\Core\SharedKernel\Application\CommandHandler` are registered on `command.bus` through `RefusalTranslatingHandler` by `Shared\DependencyInjection\RefusalTranslatingHandlersPass`; the same pass wraps every `QueryHandler` and aliases it by the name of its intent, so a class calling one asks for `RefusalTranslatingHandler $consultOrganization` (`ConsultOrganizationHandler`) (ADR 0035, 0044); the services the contexts offer each other are aliased by their interface to the handler implementing it, and asked for by their type (`ConsultMembersService $consultMembersService`, ADR 0089). Nothing is built in a constructor and no service by the code: everything is injected (`make lint` checks it, ADR 0044); the services of the hexagon are registered in `config/services.yaml` (`config/packages/messenger.yaml`: no transport, handled in the request). Those implementing `EventHandler` are tagged on `event.bus` (synchronous, `allow_no_handlers`), routed by the type of the event they take: a domain event of their context (the `Publish…` translators) or an integration event of another context (ADR 0042, 0046). `bin/console debug:messenger` (`make commands`) lists both buses.

## Hosts

- `APP_API_HOST` (`api.local.prospecter.io`), routes in `src/{Me,Prospecting,PersonalData,SignIn,Dashboard,Contacts,Exchanges}/Controller` (`config/routes.yaml`), and `src/Doc` (`/favicon.ico`, `config/routes/nelmio_api_doc.yaml`; `VersionedNelmioAssets` asks the files of Swagger UI on the CDN at the installed version of NelmioApiDocBundle); locally nginx passes `/cognito/` of the same host to the Cognito of MiniStack, for the SPA.
- Files are not the API's business: the storage app (`apps/storage`, `static.local.prospecter.io`) keeps and serves them, and `Shared\ImageResourceFactory` names their sizes by its convention (`<public url>/<size>/<path>`, ADR 0033).
