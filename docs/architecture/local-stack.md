# The local stack

What is in force; the reasons are in the records it names (`docs/adr`), read only to know why or before changing it (ADR 0090).

Everything runs in Docker, driven by make (ADR 0015, 0080): MiniStack emulates the AWS services (ADR 0048), the API and the storage run only in their Bref Lambdas on it (ADR 0055), the command line on the PHP of the Lambdas (ADR 0056), nginx serves the hosts. The commands are in the root `CLAUDE.md`, its traps in its Gotchas; where it differs from an instance on AWS: `local-vs-aws.md`.

## A stack per checkout

- Each checkout runs its own stack (ADR 0116): a Compose project named after its directory (`prospecterapp` for the main checkout, the number of a worktree), its network, its volume `ministack-data`, its Lambdas mounting its code; no container has a fixed name. make adds `docker-compose.host.yml` in the main checkout, which publishes the ports 80, 443 and 4566 of the host (https://local.prospecter.io, MiniStack for the IDE), `docker-compose.agents.yml` in a worktree, which publishes its hosts on a port of its own, the first from 8443 no other worktree keeps, kept in its `.stack-port` (`make/stack-port.sh`; `make start` prints its addresses, https://local.prospecter.io:8444 for instance), MiniStack on none. Its nginx listens on that port (`PUBLIC_PORT`), so that the journeys, in its network (ADR 0084), and Chrome on the host reach the same addresses: the apps give the browser theirs with the port (`PUBLIC_PORT_SUFFIX`, empty in their `.env`, given to the functions by `docker/lambda/deploy.sh`; `VITE_API_URL` and the live reload of Vite), the CORS of the API accept the SPA on any port, and nginx passes MiniStack the host of a private file with its port, which its signature covers. `make stop` stops the stack of the checkout and removes only the functions of its MiniStack (label `ministack.instance`); `make down` removes it with its data, once a worktree is done with.
- The images are shared by the checkouts: `prospecter-<image>:<digest of docker/<image>/ and of UID:GID>` (`make/common.mk`); a checkout changing an image builds its own tag, the others keep theirs. Run outside make, Compose takes the tag `local`. So are the downloads of Composer and pnpm (the volumes `prospecter-composer-cache` and `prospecter-pnpm-store`), the data of MiniStack staying those of each stack.
- The containers of a worktree join the slice of systemd `prospecter-agents.slice` (`cgroup_parent`, `--cgroup-parent` of Playwright): its budget, every worktree together, is written once with sudo by `make agents-slice` (`AGENTS_CPUS`, 10 CPUs, `AGENTS_MEMORY_GB`, 40, a `CPUWeight` of 50 behind the rest of the machine); without it, only the bounds of each container apply (`cpus`, `mem_limit` in `docker-compose.agents.yml`, `E2E_BOUNDS` of Playwright in `apps/front/Makefile`). Each bound is about twice the peak measured during a whole `make ci` with the journeys (2026-11-14): php 2 GB (1.1 GB, PHPStan and Rector in 2 workers, as many as its processors: 12, those of the host, doubled its memory for no time), node 2 GB (1.1 GB), nginx 64 MB (18 MB), MiniStack 8 GB (5.4 GB, the reactions of stopping to prospect, some 85 functions at once, kept until it stops), the MiniStack of the tests 512 MB (280 MB), the deployment 1 GB and 2 processors (460 MB, 7 processors), Playwright 3 GB and 4 processors (1.8 GB, 5 processors). A worktree takes some 9.5 GB at its peak, 3.6 of them its functions, out of the slice,, during the journeys running alone; the processors are what the worktrees share first, the checks of PHP of one `make ci` taking the 10 of the slice. MiniStack 1.5.27 passes to the functions it starts their memory only (`--memory=1g` in `LAMBDA_DOCKER_FLAGS`, the 1024 MB of AWS), neither their CPU nor their cgroup: they stay out of the slice, kept warm 10 minutes (`LAMBDA_WARM_TTL_SECONDS`) instead of the hour of the main checkout. Its limit of memory would derive a bound of the functions running at once, beyond which MiniStack refuses an invocation without waiting, lost when a rule made it: `LAMBDA_ACCOUNT_CONCURRENCY` is 0, unbounded.

## The API

- The API runs in a Lambda with the Bref layer (FPM runtime, `bref/bref`) behind an HTTP API of MiniStack, the repository mounted in the dev environment (ADR 0053, 0055; `make start`): `php/conf.d/bref.ini` enables the extensions the layer ships disabled (`intl`; a new extension the API needs goes there too), `TRUSTED_PROXIES` (`REMOTE_ADDR` in the function, empty for the tests) lets Symfony trust the `X-Forwarded-Proto` of the gateway. The functions write the cache and the logs of dev in the repository, PHP-FPM serving as its owner (`docker/lambda/bootstrap`); the profiler of dev keeps its profiles in `var/profiler`, out of the cache, so that a `cache:clear` (`make db`) keeps the history: read it on https://api.local.prospecter.io/_profiler, or from the `X-Debug-Token-Link` of a response in the network panel; `make profiler-clear` empties it. The tests run on the command line of the `php` container.
- The relay of the outbox (ADR 0098) is the function `prospecter-dev-relay` (`BREF_RUNTIME=function`, the service `App\Shared\Messaging\OutboxRelay`), called by a mapping on the stream of each table, publishing on the bus `prospecter-dev-integration` of MiniStack; `docker/lambda/deploy.sh` deploys it with the API, and `make db`, recreating the tables and so their streams, again (`deploy.sh relay`). MiniStack neither splits a failing batch nor stops retrying it: a record is kept a minute at most (`--maximum-record-age-in-seconds 60`), then its batch goes to the queue `prospecter-dev-relay-failures`. The delivery is `outbox` (`apps/api/.env`, ADR 0101): a command writes its item `OUTBOX#`, the relay logs each event published with its `eventId` and its correlation in the logs of dev (`apps/api/var/log/dev.log`), and the reactions run in the worker, about a second later.
- The worker (ADR 0101) is the function `prospecter-dev-worker` (`BREF_RUNTIME=function`, the service `App\Shared\Messaging\IntegrationEventConsumer`), invoked by a rule of the bus per subscription of `apps/api/config/subscriptions.json` (mounted in the image `lambda-deploy`, read with `jq`), what it refuses and what Lambda gives up kept in the queue `prospecter-dev-integration-failures`; `make db` empties both queues of the failures (`deploy.sh purge`) before recreating the tables their messages are about, so that `app:consistency:check` does not count failures of data that no longer exist; `deploy.sh relay` deploys the worker, its rules first, before the relay publishes. MiniStack invokes the target of a rule without the retries of Lambda nor its destination (spike of MiniStack 1.5.27): a failure coming from a rule is only logged, a container that does not start within the time MiniStack waits for the Docker daemon as well: a gesture of many reactions (stopping to prospect an organization of tens of exchanges) starts tens of containers at once, the daemon answering beyond the 10 s of its default, hence `MINISTACK_DOCKER_TIMEOUT` raised in `docker-compose.yml`; invoked asynchronously directly (`aws lambda invoke --invocation-type Event`, `app:integration:redrive`), the worker gets both. Its first call takes some 16 seconds: `make e2e` warms the relay and the worker first (`deploy.sh warm`), the journeys counting on a reaction within a second or so. The local bootstrap starts PHP from the root of the code, as AWS does, and, for a function of the runtime `function`, as the owner of the repository.

## The SPA

- nginx passes `https://local.prospecter.io` to the dev server of Vite (`templates/front.conf.template`), which answers a request per module, about 150 for a page loaded. A connection serves 100 000 requests (`keepalive_requests`): with the 1000 of nginx, a journey reloading its pages crossed the limit, nginx closed the connection, and the modules asked meanwhile failed in the browser (`net::ERR_FAILED`, never reaching nginx), leaving the page blank.

## The storage

- Both entries reach the app in its Lambda `prospecter-dev-storage` (ADR 0054, 0055: the mounted repository, the layers of PHP and imagick of Bref, `BREF_BINARY_RESPONSES` for the images), through `docker/nginx/storage-lambda.conf`.

## The doubles of the journeys

- nginx serves on the Docker network only the double of the geocoder of the IGN (`http://nginx:8081/search`, `conf.d/geocoder-double.conf`); `make e2e` points the API at it while the journeys run (`docker/lambda/deploy.sh geocoder <url>`), then at the service of `apps/api/.env` again (ADR 0092, `docs/architecture/tests.md`).
