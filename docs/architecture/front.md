# Front architecture (apps/front)

A React single page application talking to the API (`apps/api`) over JSON, its members signed in by SRP on a Cognito user pool (ADR 0052).

## Stack and why

| Concern | Choice | Why |
|---|---|---|
| UI library | React 19 + React Compiler | The compiler memoizes components and hooks: no hand-written `useMemo`/`useCallback`. |
| Language | TypeScript 7 (native compiler), strict | Fast type checking; `noUncheckedIndexedAccess` catches undefined array access. |
| Build | Vite 8 | Instant dev server and HMR, Rolldown production build. |
| Routing | TanStack Router (file routes) | Fully typed links, params and search params; automatic code splitting per route; loaders. |
| Server state | TanStack Query | Cache, request deduplication, background refresh, targeted invalidation. |
| API client | openapi-fetch + openapi-react-query | Types generated from the API contract: a renamed field breaks the build, not production. |
| Client state | Zustand | Tiny store for UI preferences only (theme, sidebar). |
| Forms | react-hook-form + zod | Uncontrolled inputs (no re-render per key), schema validation mirroring the API. |
| Auth | aws-amplify v6 (`aws-amplify/auth`) | SRP on the Cognito user pool from our own screen (the password never leaves the browser), token refresh. |
| UI kit | shadcn/ui (Radix) + Tailwind CSS 4 | Accessible primitives, code owned by the project (see `design-system.md`). |
| Maps | MapLibre + OpenFreeMap | Open source vector maps, no API key; loaded lazily. |
| i18n | react-i18next, typed keys | French today, other languages without touching the screens. |
| Quality | Biome, Vitest + Testing Library, Playwright | One fast linter/formatter; component tests as a user would act, the screens tested there; end-to-end journeys only for what no other test links (ADR 0122, `docs/architecture/tests.md`). |

Dependency rule: `shared` depends on nothing of the app; a `feature` depends only on `shared`; `routes` and `app` compose features. Query key prefixes used by several features live in `shared/api/keys.ts`.

## State: each kind in its place

| State | Where | Example |
|---|---|---|
| Server data | TanStack Query cache | organizations, my account, dashboard |
| URL | Router search params, validated by zod | `?q=acme` on the organizations list |
| UI preferences | Zustand, persisted in localStorage | theme, collapsed sidebar |
| Form | react-hook-form | the section being edited |
| Session | aws-amplify v6 (sessionStorage) | access, id and refresh tokens |
| Local UI | `useState` | a dialog being open |

Never copy server data into Zustand or `useState`: read it from the query, the cache is the single source of truth.

## Data flow and performance

- Queries are declared once as options (`organizationQuery(id)` in `features/*/queries.ts`) and reused by route loaders and components.
- Route loaders call `queryClient.ensureQueryData(...)`: the data is fetched before the page renders (no loading waterfall), and with `defaultPreload: 'intent'` hovering a link starts loading its code and data. A loader that sends a command or makes the API call a service outside (the check of the connectors with their providers) does it only on the load, never on a preload (its argument `preload`); the SPA of the Vitest tests preloads like the app (`app/preloading.ts`).
- A query a loader shares with the app shell (the account, read by the user menu) is loaded by `ensureSharedQueryData` (`shared/api`): the menu, mounted twice by StrictMode while the request runs, makes TanStack Query cancel it, and `ensureQueryData` would fail the page on that cancellation; it waits for the request started again.
- Pages read with `useSuspenseQuery`: no undefined checks, the route `pendingComponent` shows a skeleton when loading takes time. Lists are the exception: `useInfiniteQuery` with `keepPreviousData` (below).
- `staleTime` 30 s: navigating back and forth does not refetch; data refreshes in the background when the window regains focus.
- A list comes a slice after the other (ADR 0049): `infiniteQueryOptions` on the typed client (`organizationSlicesQuery`, `contactSlicesQuery`), the cursor read in the link `next` of a slice (`shared/api/slices.ts`), "Charger plus" asks for the next one (a timeline, of a contact or of an organization, also when its end scrolls into view: `timelineQuery`, `organizationTimelineQuery` and the shared `TimelineCard` of `features/exchanges`, `shared/hooks/use-when-visible.ts`); no page number, no total. A list keeps the previous search on screen while the next loads (`placeholderData: keepPreviousData`); the search input is debounced (300 ms) and written to the URL.
- Mutations put the returned resource directly in the cache (`setQueryData`), then invalidate only the lists that may change; invalidated queries refetch only if displayed. A mutation showing its result before the answer (`useMoveInTheCalendar`) keeps what the queries held in `onMutate`, puts it back in `onError`, and reads them again in `onSettled`.
- A listener on `window` or `document` reads the latest props through `useEffectEvent` and is registered once (`useCalendarShortcuts`).
- A gesture easy to regret without a form (marking a planned exchange missed, cancelling it) is sent once its toast, offering « Annuler » for a few seconds, is gone (`useUndoable` of `features/exchanges/mutations.ts`): what follows it is in the options of its mutation, which run even once its sheet is closed: what must follow a mutation whose component may be gone goes in the options of `useMutation`, never in the callbacks given to `mutate`, which TanStack Query calls only while it is mounted. An exchange done or noted proposes « Planifier la suite » with the same interlocutor and channel, left in a click (`features/exchanges/components/follow-up.tsx`).
- What the reactions to a gesture change is written after it, in the worker of the API, a second or so later (ADR 0101): its mutation reads those queries again at once and once after the reactions, two and a half seconds later (`readAgainAfterTheReactions` of `shared/api/reactions.ts`, `AFTER_THE_REACTIONS_MS`), never in a burst: only the queries displayed, the others marked to read when they are shown again; each once at each moment, however many times the gesture names it, a read under way at once being the one awaited, one still under way after the reactions started anew; gestures following each other read once after the reactions to the last: the contacts and the exchanges, those to come of the organizations among them, after one is removed or forgotten (`readTheExchangesAgain` of `shared/api/exchanges.ts`), the contacts after the prospecting of an organization stops. A change the member must see at once, whatever the reactions take, is written into the cache from the answer of the API instead, then what the reaction changes is read apart from the cache until it is seen, and only then put in the cache with the queries whose links depend on it read again: a contact collected on the card of an organization appears in its contacts from the contact the API answers, its contacts read until they hold it (`UNTIL_THE_CONTACT_IS_ATTACHED_MS`, some twenty seconds), the organization, the contact and its organizations then read again for what the attachment offers (removing the contact, its exchanges, its to-dos, the organizations on its page) (`useCollectContact`).
- The tags put by hand on an organization or a contact (`features/tags`, ADR 0138) are a line of chips under the header of its card when it carries the link `tags`, each taken off by its cross, « Ajouter un tag » opening a picker of the tags proposed to the account (`TagPicker`): the predefined ones by family, then those of the account, those carried left out, filtered by what is typed whatever its case, accents and mark, or created as typed, Enter picking the first; the API writes the tag one way and answers the tags, put in the cache, the tags proposed read again. The form of a new organization offers its tags too (`TagsField`, given by the route), put once it is created; a tag refused then is told by its toast, the organization opening all the same. The predefined tags and those of the account look alike; the automatic ones will look apart.
- The to-dos of a contact or of an organization are read whole, never sliced (ADR 0113), in the section « À faire » of its card when it carries the link `toDos` (`features/to-dos`): « Ajouter » in its header, or in its middle while nothing is to do, opens a dialog with the form of a revision, its text focused, the shortcuts of its due day (`DUE_SHORTCUTS`), « Ajouter et en noter une autre » keeping it open for the next one, those overdue in red (`isOverdue`, in the time of the browser), those done folded; ticking one off proposes « Noter l'échange ? », which opens the form of an exchange with its contact, or with the organization itself, at the moment of the click (`useNoteTheExchangeProposal`).
- The detail of a planned exchange (`ExchangePanel`, in its sheet and in the dialog of the calendar) says where its push into the Google calendar of the member stands (`features/exchanges/components/google-sync.tsx`, ADR 0133): the « G » of Google (`shared/ui/google-logo.tsx`) with a check, a clock or a warning, its reason and its moment on hover, « Réessayer » once Google refused it; nothing while it is not pushed into theirs; pending for its push (no reason), it is read again as an awaited link, five times at most, stopping once it is no longer (`googleSyncQuery`), never while it awaits the reconnection of the member. The form of a video call offers « Créer un lien Google Meet », checked, while the connections the app keeps for its banner say Google connected and no link is written (`MeetLink` of `plan-form.tsx`, read from their cache, never asked again by the form); the detail of a video call awaiting that link (`linkAwaited`) reads it again five times at most, after 1, 2, 4, 8 then 15 seconds, stopping once it came (`exchangeQuery`, `awaited-push.ts`, ADR 0137), never a steady polling. A gesture on an exchange reads it again once its reactions ran (`readAgainAfterTheReactions`).
- A file joined to an exchange goes from the browser to S3 with a form the API signs, then is joined by its upload; it is downloaded by a link signed for a minute the API answers, the link shown being the API's (`features/exchanges/attachments.ts`, ADR 0077). A new exchange tells its address in `Location`, for its files to be joined once it is noted.
- Code splitting: one chunk per route (router plugin), MapLibre loaded with `lazy()` only on pages with a map.

## Navigation

- "Retour" behaves like the browser back button (`shared/ui/back-button.tsx`): from the dashboard map it returns to the dashboard, from a filtered list to that list with its search. Opened from a bookmark, it falls back to a link.
- A resource page is made of sections (`shared/ui/editable-section.tsx`): each shows one part of the resource and changes it in place through its own small form (`shared/forms/section-form.tsx`), one API intent each (ADR 0025); only the creation has a full form. A section is editable (`editable`), an image changeable (`onUpload`), a button shown only when the resource carries the link of that intention (`organization._links.relocate`): the API decides what is possible (ADR 0027), the front never re-implements it.
- A creation form is left with `useGoBack` (cancel), and replaces itself with the new page (`replace: true`): the history never holds a form already done with.
- The dashboard shows my day above its figures (`features/exchanges/my-day`, composed by the route as the calendar): « Aujourd’hui », what I still have planned today, the time left before each (« dans 25 min »), the one in progress set apart, one whose hour passed « À traiter » with « Fait », which opens its dialog on the report, and « Manqué » when it carries their links, « Rejoindre » a video call, « Appeler » a call by the number its detail gives; « À venir », the next five (« demain 9h00 », « lundi 14h00 »), and « Voir le calendrier »; an exchange opens in the dialog of the calendar; nothing planned today proposes « Planifier » in the calendar of the day when the day carries `searchContacts`. It is read for the day of the browser (`myDayQuery`), its loader starting it without waiting for it, its cards suspended on their own (`MyDaySkeleton`): a day slow to answer leaves the rest of the dashboard shown; again after every gesture on an exchange (`queryKeys.myDay`, beside the calendar).
- Above them, the dashboard shows « À traiter » while something is (`features/exchanges/to-process`): what I planned whose end has passed and I have not handled yet, whatever its day, the oldest first, then my to-dos of the day and late, « Pour aujourd’hui » or « En retard de 3 jours », ticked off in place (`ToDoLine` of `features/to-dos`, given by the route) (`exchangesToProcessQuery`, sent with the time zone of the browser, `readerTimeZone()`, read again every five minutes and after every gesture on an exchange or a to-do, `queryKeys.exchangesToProcess`, ADR 0134); each line offers « Fait », which opens its dialog on the report, then « Planifier la suite », « Manqué » and « Annulé », the line taken away at once while its toast may take the gesture back (`useUndoable`), and « Déplacer », which opens its dialog on the move, as its links say; « Tout est à jour 🎉 » once the last one I processed leaves the card. The entry « Tableau de bord » of the menu counts them, exchanges and to-dos (`ToProcessCount`).
- The reminders of my exchanges (`features/exchanges/reminders`, composed by the `_app` layout with my settings, `/api/me/reminders`): entirely in the SPA, the server sending nothing, while the application is open. They read my day (`useMyDayToRemind`, the key of `myDayQuery`, its own observer disabled: today and the next ones, at once, again every 5 minutes, in the background too, and once after a gesture changed it, when the reads of the page and its reactions are done, never along with them, which it would delay) and wake at the moment of the next one (`schedule.ts`): `minutesBefore` an exchange still planned, at once when the application opens after that moment and before the exchange, never once it started a minute ago; an exchange moved is another reminder. A reminder is a toast until it is closed: its channel, its interlocutor, their organization and its hour, « Rejoindre », « Appeler » or « Itinéraire » by its channel, « Dans 5 min » showing it again then, a click opening the exchange on the card of its contact or of its organization (`?exchange=<id>`, the sheet of its detail over the card). The reminders shown are kept in `localStorage` (`reminded.ts`), read by every tab of the browser, which learn of a change by its `storage` event: a reminder shows in one tab only, a tab in the background letting one in front show it first (2 s); in the background, a notification of the browser (once allowed, `shared/lib/browser-notifications.ts`) brings the member back to the tab and opens the exchange, and the title of the tab blinks (`shared/lib/blinking-title.ts`) until it comes in front. My to-dos of the day are reminded alike (`ToDoReminders`, `to-do-schedule.ts`, read among what I have to process): one with an hour `minutesBefore` it, one without at 9:00 on its day, or once the application opens later that day, a toast opening its day in the calendar (ADR 0134).
- The dashboard shows the five figures the API counts, as they come (`features/dashboard/components/dashboard-figures.tsx`): none is computed in the browser from a list or the markers, which stop at 1 000. A figure is counted by the reactions to a gesture, about a second after it: the gestures changing one (starting, changing, relocating or stopping an organization, collecting or forgetting a contact, noting, correcting or erasing an exchange) read the dashboard again once they ran (`readAgainAfterTheReactions`, `shared/api/reactions.ts`).
- The calendar of the member (`/calendar`, « Calendrier » in the main navigation, `features/exchanges/calendar`, ADR 0115): month (the default, a list « Agenda » on a phone), week, day and agenda, the view and the day in the URL (`?view=&date=`); a grid of the project on the tokens, with the dates of the browser (`dates.ts`: a period in whole days, sent with the offset of each bound; `time-grid.ts`: the exchanges of a day side by side when they overlap, placed by custom properties of the classes, the one place a position is data rather than style). Each period shown is a query of its own (`calendarQuery`), the next and the previous one read on the hover of their arrow, the three days around a day read ahead; every gesture on an exchange reads the calendar again (`queryKeys.myCalendar`). An exchange shows its look by its status (to come in full colour, done faded, missed hatched, cancelled struck through, planned and passed « À traiter » in the warning colour) and opens in a dialog (`exchange-dialog.tsx`): its detail and what it offers (`ExchangePanel`, as in its sheet), the contact in short (`ContactSummary` of `features/contacts`, given by the route, a feature never importing another; read masked, their name and organizations only, ADR 0129) and their last three exchanges, « Ouvrir la fiche ». One carrying the link `move` (ADR 0119) is dragged by the pointer to another quarter of an hour or another day in the week and the day, to another day at its hour in the month, or stretched by its end (`gestures.ts`, `use-gestures.ts`: once grabbed, the window follows the pointer, the exchange drawn again in another column); it shows where it is dropped at once, set back where it was when the API refuses, its toast moving it back when the response carries the link `moveBack` (ADR 0135: its former moment to come; told without the offer otherwise) (`useMoveInTheCalendar`), however long the member takes, until another exchange is moved or opened (it may be moved from its dialog) or the calendar is left: one toast, never closing on its own, a slow answer of the API delaying it, a move answered once the calendar is left told without it. A free slot of the week or of the day, clicked or dragged for its duration, when the calendar carries the link `searchContacts`, opens the planning there (`plan-in-a-slot.tsx`) with a contact or an organization searched as everywhere (`InterlocutorSearch` of `features/organizations`, given by the route), the form offered when their timeline carries `planExchange`. The keys T, ← →, M S J A drive it, not while a field is typed in nor in a dialog over it (`shortcuts.ts`). It shows my to-dos too (ADR 0134), « Tout », « Échanges » or « À faire » as filtered: those of a day without an hour in a band above the hours of the week and of the day, those with an hour at it without a duration, first in a day of the month and of the agenda, on the day written whatever the time zone of the browser (`to-dos.ts`); each ticked off or unticked in place by its box (`ToDoBox` of `features/to-dos`, given by the route), done greyed and struck, dragged to another day when it carries `revise`, its hour kept (`toDoDrop`, a drag of the browser, the revision given by the route; the keyboard revises it from its card). What the API says late (`late`, read with the time zone of the browser) shows the token `warning` on its edge, an icon and « En retard », never the colour alone, one pulse when shown and none under `prefers-reduced-motion` (`animate-late-once`).
- The configuration of the member (`/settings`, « Configuration » in the user menu, `features/settings`) is made of sections, the one shown in the URL (`?section=`), a side navigation on a computer, tabs on a phone: a setting follows the account, saved at once and confirmed by a toast (the reminders, `/api/me/reminders`); the connectors (`features/connectors`, ADR 0120) are checked with their providers each time their section opens (`checkMyConnections`, its answer kept as the state `ReconnectBanner` reads above every page; while Google does not answer, `googleUnreachable`, the connections read as last seen, said unchecked, and still disconnected), Google said unavailable, neither connected nor reconnected, while the connections lack their link `connectGoogle` (the account has no client of Google), an administrator configuring that client below, with the redirect URI to declare in it, its secret typed and never shown again, while the connections carry the link `googleClient` (`GoogleClientCard`, ADR 0125), the card of Google counting the exchanges to come of the member synced and failed there, « Tout réessayer » while one failed (`retryFailed`, ADR 0133), Google bringing the member back to `/settings/connectors/google`, the page giving the API its code once, then going back to the section with a toast; the theme stays in the user menu, a preference of the device.
- Map markers open a quick look (`features/organizations/components/organization-preview.tsx`, rendered by `GeoMap`'s `renderPopup`), which loads the organization into the cache: its page then opens instantly.

## API access

- `pnpm api:types` (or `make api-doc` from the root) regenerates `shared/api/schema.d.ts` from `apps/api/openapi.json`; `api` calls the API with the access token, what a member signs in with included (`/api/me/sign-in`).
- `api.queryOptions('get', '/api/organizations/{id}', { params })` / `api.useMutation('patch', ...)`: path, params, body and response are typed. Other options of a query go in its fourth argument (`api.queryOptions('get', '/api/me', undefined, { refetchInterval })`), typed by TanStack Query, never spread over it with a hand-written type. A `refetchInterval` that must run while the tab is in the background sets `refetchIntervalInBackground: true`: without it, TanStack Query reads again only while the window has the focus.
- The fetch middleware adds `Authorization: Bearer`; on a 401 it renews the token once with the refresh token, otherwise it sends the user to sign in.
- Form values have the shape of the API input (`street` in the address section, `address.street` in the creation form), so the `propertyPath` of each API violation is the form field name. Groups of fields shared by several forms live in `shared/forms` (`AddressFields`, `ContactDetailsFields`, `LegalIdentityFields`, `PersonNameFields`, with their zod schema and conversions); their `path` option nests them in a bigger form.
- A field shows its error through `FormField`, which subscribes to it (`useFormState`): the React Compiler memoizes components receiving the same `form`, so a group of fields would not render a new error by itself.
- Errors are RFC 9457 problem details (`shared/api/problem.ts`), a refusal worded from its `reason` and `context` by `refusals` of `fr.ts`, else as the API worded it (ADR 0073): `applyViolations()` puts the server validation errors on the form fields; other mutation errors raise a toast (`query-client.ts`), unless the mutation sets `meta: { silentValidation: true }` and handles 422 in its form.
- Uploads are separate multipart endpoints (`shared/api/upload.ts`).
- An image comes in sizes (`smallUrl` 96 px, `mediumUrl` 256 px, `url` the original): show the smallest that covers the displayed size twice (high density screens): `smallUrl` for avatars, markers and cards, `mediumUrl` for an image section.
- Ids are UUIDs: a route param that is not one is a 404 before any request (`shared/lib/route-params.ts`), and an API 404 in a loader becomes the same not found page.

## Authentication

See `docs/architecture/auth.md`. In the SPA: `shared/auth/session.ts` signs in on the user pool the API names (`GET /api/user-pool`) and gives the access token, renewed once expired; the `_app` layout route guards every page with it and sends an anonymous visitor to the sign-in screen, `routes/auth/sign-in.tsx` (`features/sign-in`), which goes back to the page asked for once signed in (ADR 0037, 0052). Signed in, a member whose profile has no name completes it before anything else, when the account carries the links `changeMyName` and `changeMyContactDetails`: the `_app` layout loads the account and shows « Complétez votre profil » in place of the shell (`features/account/components/complete-my-profile-form.tsx`), their login email proposed for their profile, sent by the intentions of the account, the email then the name, each its own use case, then opens the home page (ADR 0100). Their profile is created by a reaction to their registration, a moment after it (ADR 0101): until then their account is refused for a person not found (`unknownPerson`), and the layout shows « Votre profil est en cours de préparation… » (`features/account/components/my-profile-being-prepared.tsx`), reading the account again after 1, 2, 4, 8, 16 s… until it exists, then « Réessayez plus tard » once a minute waited (`nextReadingOfMyProfile`). That screen, and the error of the layout when the account cannot be read, offer « Se déconnecter » (`app/layout/sign-out.tsx`), the user menu being out of reach. The sign-in screen and this one are pages of one card outside the shell (`app/layout/card-page.tsx`).

## Adding a screen

1. If the API changed, `make api-doc`.
2. In `features/<feature>/`: query options, mutations (update the cache), zod schema mirroring the API input, components.
3. A route file in `routes/_app/...` with a `loader` (`ensureQueryData`), `pendingComponent`, `errorComponent`, and the page component.
4. Texts in `shared/i18n/fr.ts`.
5. A component test for the behaviour (the SPA on its routes when it crosses the router or the layout); a Playwright journey only for what no other test links (ADR 0122).

## Rules

- Respect the folders: `routes/` thin (loader + page), `features/<feature>/` (queries, mutations, schema, components), `shared/` business agnostic. A feature never imports another feature; shared query keys go to `shared/api/keys.ts`. `shared` imports nothing from `app`, `features` or `routes` (Biome `noRestrictedImports` refuses it).
- Server data only through TanStack Query with the generated client `api` (what a member signs in with included: `/api/me/sign-in`). Signing in, renewing the token and signing out go through `shared/auth/session.ts` only (Cognito). Never `fetch` by hand (but to send a private file to S3 with the form the API signed, `features/exchanges/attachments.ts`, ADR 0077), never copy server data into `useState` or Zustand. Mutations update the cache with the returned resource, then invalidate the affected list prefixes.
- Route data: `loader` with `context.queryClient.ensureQueryData(...)`, page with `useSuspenseQuery`, plus `pendingComponent` and `errorComponent`; a page that cannot load at all (the api unreachable) falls to the `PageError` of the root route. Search state in validated search params; a list comes in slices (`useInfiniteQuery`, the link `next`, "Charger plus", ADR 0049), never numbered pages.
- Never write `useMemo`/`useCallback`/`memo` for performance: the React Compiler does it.
- After an API change: `make api-doc` (regenerates `src/shared/api/schema.d.ts`, never edited by hand) and fix the type errors.
- Forms: react-hook-form + zod schema mirroring the API constraints; show server violations with `applyViolations`. A resource is changed section by section, one intent each: `EditableSection` + `SectionForm`, shared field groups in `shared/forms`, fields through `FormField` (it subscribes to its own error; the React Compiler would not re-render a memoized group). `Field` gives its label, error and hint to its direct child: a controlled field puts its `Controller` around the `FormField`, never inside (`CountryField`), or the control has no name for a screen reader. Only a creation has a full form. A form emptied for the next entry is mounted again with a new `key` (`AddToDoDialog` of the to-dos), never `form.reset` in place: `reset` forgets which fields are mounted until they register again on the next render, which the React Compiler skips, the inputs then showing values the form no longer reads, even with `keepFieldsRef` from the second reset on. Show an action only when the resource carries its link (`_links.<intention>`), never from the data itself.
- UI: compose `shared/ui` components and semantic tokens (`bg-card`, `text-muted-foreground`…), no raw colors, no inline styles: a `style` carries only CSS custom properties, for a position computed from data that the Tailwind classes read (`time-grid-view.tsx`: `--start`, `--length`, `--lane`, `--lanes`, `--now`). Every text shown or announced (to the screen readers too: `sr-only`, `aria-label`, `title`, `placeholder`, `alt`) through `t()` with a key added to `shared/i18n/fr.ts` (keys are typed); `make lint` refuses one written in the code (`lint/translated-texts.grit`, ADR 0093), never an error thrown or a log. The texts of a library come from `fr.ts` too: MapLibre by its `locale` (`map-view.tsx`), Sonner by `closeButtonAriaLabel` (`shared/ui/sonner.tsx`), a component of shadcn added by its props. « de » before a name is written `{{name, de}}`: the formatter `de` (`shared/i18n/de.ts`) elides it before a vowel (« d’Anaïs », « de Pauline », never before an h).
- Navigation: "Retour" goes back in history (`shared/ui/back-button.tsx`, fallback link when opened directly), a creation form is left with `useGoBack` and replaces itself (`replace: true`), so going back never lands on a form already submitted or cancelled.
- Accessibility: every control labelled (`Field`), icons `aria-hidden` next to text, keyboard reachable.
- Style: Biome (single quotes, no semicolons, 110 columns), `import type` for types, `@/` alias for `src/`.
