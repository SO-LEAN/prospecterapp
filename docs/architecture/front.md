# Front architecture (apps/front)

This document states the rules in force. The decision records (`docs/adr`) explain why: read them only for that, or before changing a rule (ADR 0090).

A React single page application that talks JSON to the API (`apps/api`). Members sign in by SRP on a Cognito user pool (ADR 0052).

## Stack and why

| Concern | Choice | Why |
|---|---|---|
| UI library | React 19 + React Compiler | The compiler memoizes components and hooks: no hand-written `useMemo`/`useCallback`. |
| Language | TypeScript 7 (native compiler), strict | Fast type checking; `noUncheckedIndexedAccess` catches undefined array access. |
| Build | Vite 8 | Instant dev server and HMR, Rolldown production build. |
| Routing | TanStack Router (file routes) | Fully typed links, params and search params; automatic code splitting per route; loaders. |
| Server state | TanStack Query | Cache, request deduplication, background refresh, targeted invalidation. |
| API client | openapi-fetch + openapi-react-query | Types generated from the API contract: a renamed field breaks the build, not production. |
| Client state | Zustand | Tiny store for UI preferences only (theme, sidebar). |
| Forms | react-hook-form + zod | Uncontrolled inputs (no re-render per key), schema validation mirroring the API. |
| Auth | aws-amplify v6 (`aws-amplify/auth`) | SRP on the Cognito user pool from our own screen (the password never leaves the browser), token refresh. |
| UI kit | shadcn/ui (Radix) + Tailwind CSS 4 | Accessible primitives, code owned by the project (see `design-system.md`). |
| Phone numbers | libphonenumber-js | The libphonenumber metadata, the same library the core reads numbers with. A phone number is formatted as it is typed (`shared/forms/phone.ts`, `AsYouType`, French numbers without their country code) and written in international format (`parsePhoneNumberFromString`). |
| Maps | MapLibre + OpenFreeMap | Open source vector maps, no API key; loaded lazily. |
| i18n | react-i18next, typed keys | French today, other languages without touching the screens. |
| Quality | Biome, Vitest + Testing Library, Playwright | One fast linter and formatter; component tests that act as a user would, and screens are tested there; end-to-end journeys only for what no other test covers (ADR 0122, `docs/architecture/tests.md`). |

Dependency rule: `shared` depends on nothing in the app. A `feature` depends only on `shared`. `routes` and `app` compose features. Query key prefixes that several features use live in `shared/api/keys.ts`.

## State: each kind in its place

| State | Where | Example |
|---|---|---|
| Server data | TanStack Query cache | organizations, my account, dashboard |
| URL | Router search params, validated by zod | `?q=acme` on the organizations list |
| UI preferences | Zustand, persisted in localStorage | theme, collapsed sidebar |
| Form | react-hook-form | the section being edited |
| Session | aws-amplify v6 (sessionStorage) | access, id and refresh tokens |
| Local UI | `useState` | a dialog being open |

Never copy server data into Zustand or `useState`: read it from the query. The cache is the single source of truth.

## Data flow and performance

- Queries are declared once as options (`organizationQuery(id)` in `features/*/queries.ts`) and reused by route loaders and components.
- Route loaders call `queryClient.ensureQueryData(...)`, so the data is fetched before the page renders (no loading waterfall). With `defaultPreload: 'intent'`, hovering a link starts loading its code and data. A loader that sends a command, or makes the API call an outside service (checking the connectors with their providers), does so only on load, never on preload (its `preload` argument). The SPA in the Vitest tests preloads like the app (`app/preloading.ts`).
- A query that a loader shares with the app shell (the account, which the user menu reads) is loaded with `ensureSharedQueryData` (`shared/api`). StrictMode mounts the menu twice while the request runs, which makes TanStack Query cancel the request. `ensureQueryData` would fail the page on that cancellation. `ensureSharedQueryData` waits for the restarted request instead.
- Pages read with `useSuspenseQuery`: no undefined checks, and the route's `pendingComponent` shows a skeleton when loading takes time. Lists are the exception: `useInfiniteQuery` with `keepPreviousData` (below).
- `staleTime` is 30 s, so navigating back and forth does not refetch. Data refreshes in the background when the window regains focus.
- A list comes one slice at a time (ADR 0049). It uses `infiniteQueryOptions` on the typed client (`organizationSlicesQuery`, `contactSlicesQuery`), and reads the cursor from a slice's `next` link (`shared/api/slices.ts`). "Charger plus" asks for the next slice. A timeline, for a contact or an organization, also loads more when its end scrolls into view (`timelineQuery`, `organizationTimelineQuery` and the shared `TimelineCard` in `features/exchanges`, `shared/hooks/use-when-visible.ts`). There are no page numbers and no total, except the number of contacts found by tags (`taggedContactSlicesQuery`, ADR 0143). Contacts are searched either by text or by the tags they all carry, never both. The chosen tags are kept in the URL (`/contacts?tags=ESN,EMAIL`, `shared/api/tagged-contacts.ts`, with the `taggedContactSlicesQuery` query that a campaign's target reads too). They are added through `TagsFilter`, which proposes every tag, automatic ones included. Each tag shown on a contact or an organization links to that list. A list keeps the previous search on screen while the next one loads (`placeholderData: keepPreviousData`). The search input is debounced (300 ms) and written to the URL. The contacts list offers « Nouveau contact » while it carries `collect` (`/contacts/new`). Its form is the organization card's form (`CollectContactForm`), led by the organization to choose (`OrganizationChoice`). The choice finds the prospected organizations by the start of their name. When none matches, it links to « Commencer à prospecter ».
- Mutations put the returned resource straight into the cache (`setQueryData`), then invalidate only the lists that may change. Invalidated queries refetch only if displayed. A mutation that shows its result before the answer arrives (`useMoveInTheCalendar`) saves what the queries held in `onMutate`, restores it in `onError`, and reads them again in `onSettled`.
- A listener on `window` or `document` reads the latest props through `useEffectEvent` and is registered once (`useCalendarShortcuts`).
- A gesture that is easy to regret and has no form (marking a planned exchange missed, cancelling it) shows a toast that offers « Annuler » for a few seconds. The gesture is sent only once that toast is gone (`useUndoable` in `features/exchanges/mutations.ts`). What follows the gesture lives in its mutation's options, which run even after its sheet is closed. In general, what must follow a mutation whose component may be gone goes in the `useMutation` options, never in the callbacks passed to `mutate`: TanStack Query calls those only while the component is mounted. An exchange that is done or logged offers « Planifier la suite » with the same interlocutor and channel. The member dismisses that offer in one click (`features/exchanges/components/follow-up.tsx`).
- The reactions to a gesture write their changes after it, in the API worker, a second or so later (ADR 0101). The gesture's mutation reads those queries again immediately, then once more after the reactions, two and a half seconds later (`readAgainAfterTheReactions` in `shared/api/reactions.ts`, `AFTER_THE_REACTIONS_MS`), never in a burst:
  - only the displayed queries are read; the others are marked to be read when they are shown again;
  - each query is read once at each moment, however many times the gesture names it. A read already under way at the first moment is the one awaited. A read still under way after the reactions is started again;
  - consecutive gestures read once, after the last one's reactions.
  This covers the contacts and the exchanges (among them the organizations' upcoming exchanges) after a contact is removed or forgotten (`readTheExchangesAgain` in `shared/api/exchanges.ts`), and the contacts after prospecting an organization stops. A change the member must see immediately, however long the reactions take, is written into the cache from the API's answer instead. What the reaction changes is then read outside the cache until it shows up. It is put in the cache only then, and the queries whose links depend on it are read again. For example, a contact collected on an organization's card appears among its contacts from the contact the API returns. The organization's contacts are read until they include it (`UNTIL_THE_CONTACT_IS_ATTACHED_MS`, about twenty seconds). Then the organization, the contact and the contact's organizations are read again for what the attachment offers (removing the contact, its exchanges, its to-dos, the organizations on its page) (`useCollectContact`).
- Manual tags on an organization or a contact (`features/tags`, ADR 0138) appear as a row of chips under its card's header when it carries the `tags` link. Each chip is removed with its cross. « Ajouter un tag » opens a picker of the tags offered to the account (`TagPicker`). It shows the predefined tags by family, then the account's own, and leaves out those already carried. The picker filters on what is typed, ignoring case, accents and marks, or creates the tag as typed. Enter picks the first one. The API writes the tag one way and returns the tags, which go into the cache. The offered tags are then read again. The new organization form offers tags too (`TagsField`, passed in by the route). They are added once the organization is created. A tag refused at that point is reported in a toast, and the organization opens anyway. Predefined tags and account tags look the same.
  - After its own tags, a contact shows the tags it inherits (ADR 0141), without a cross. « Hérité de ACME » names the organizations they come from (the route names them, from the contact's organizations). It then shows the automatic tags, dashed with a spark and labelled « Automatique ». Each one is explained on hover and on focus (`ExplainedTag`).
  - After its own tags, an organization shows the automatic tags derived from its location, « Déduit de l’adresse », which its contacts inherit (ADR 0142).
  - The contacts list shows every tag each contact carries, in small.
  - Every tag shown, whether manual, inherited or automatic, links to the contacts carrying it (ADR 0143).
  - When searching contacts (`searching`), the picker lists the automatic tags last and creates none.
  - Changing a contact's details, or an organization's contacts, reads its tags again once the reactions have run (`queryKeys.contactTags`). Changing an organization's tags reads the contacts' tags again immediately, since inherited tags are resolved on read. Creating or moving an organization reads its tags and the contacts' tags again once the reactions have recorded its location (`queryKeys.organizationTags`).
- The team's campaigns live at `/campaigns` (`features/campaigns`, ADR 0144). « Campagnes » appears in the main navigation when my account carries the `campaigns` link. The campaigns are read in full: their status, channel and author, and their progress. The progress, « handled / targeted », counts the recipients processed and dismissed (`handledIn`) out of those targeted, as the api counts them.
  - « Nouvelle campagne » prepares a draft (`/campaigns/new`), which opens its page (`/campaigns/$campaignId`). The left side holds its form, revised as a whole: tags chosen with the contacts' `TagsFilter` (passed in by the route), a subject for e-mail only, and an explanation of the message variables. The right side, on both pages, shows the contacts it targets, updated as the form is typed (`useLiveTarget`). They come from a tag search (`taggedContactSlicesQuery` in `shared/api/tagged-contacts.ts`, as for the contacts list) on the chosen tags plus the channel's tag (`targetedTagsOf`, named as the api names them). Nothing is requested while no tag is chosen, or while more than 5 are chosen, counting the channel's tag. Once the draft is prepared, the right side shows the saved message as the api renders it for the hovered or focused contact (`campaignMessageQuery`). The front never renders the message. The right side says so while the form differs from the saved message. « Supprimer » is in its menu while it carries `discard`.
  - « Figer la liste » (`FreezeCampaign`, while it carries `freeze`) asks for confirmation. The search then stops changing. Once frozen (it carries `recipients`), its channel is disabled and its tags are shown as badges. The right side holds its recipients, read in full (`campaignRecipientsQuery`, `CampaignRecipients`). Each one shows its status, and a cross while it carries `remove`. The hovered one shows the message preview. « Ajouter » opens a dialog with two tabs (`AddRecipients`, `shared/ui/tabs.tsx`). « Par tags » is a `TagsFilter` that previews the contacts found by those tags plus the channel's tag, leaving out those already kept. « Un contact » is a contact search by name (`contactSlicesQuery`).
  - « Démarrer la campagne » (`StartCampaign`, while it carries `start`) asks for confirmation. The list and the message then stop changing. While it is frozen, erasing its contacts may leave it with none. It then says so instead of showing its list (`campaigns.recipients.emptied`), and offers no « Démarrer la campagne ». « Supprimer » stays in its menu.
  - Once started, it runs as a task list (`CampaignRun`, ADR 0145), with its progress in its header (`CampaignProgress`). The left side lists its recipients, those to handle first (they carry `noteExchange`), each with its status. An erased contact is named « Contact effacé ». The right side shows the chosen recipient, by default the first to handle. It shows how its channel reaches them (`meansOf`) and the message as the api renders it for them. It offers « Copier » (a toast confirms the copy) and « Ouvrir » (`openingOf`: `mailto:` with the subject and the message, `sms:` with the message, `tel:`, or the LinkedIn profile in a new tab). It also offers « Noter un échange », prefilled (the campaign's channel, outbound, now, the message as its text). There, « Enregistrer » logs it and « Écarter » dismisses the recipient for the reason typed. Once nobody is left to handle, a sentence replaces the panel and says the campaign has ended (`CampaignEnded`, `campaigns.run.ended`), above its summary. The N key moves to the next recipient to handle without logging anything, as a sentence under « Suivant » explains (`campaigns.run.nextByKey`). Campaigns processes a recipient shortly after its exchange is logged. The page marks the recipient handled immediately and opens the next one to handle. Meanwhile the campaign, its recipients and the timelines are read again in the background.
  - Once it is stopped or ended (it carries `recipients` but not `revise`), the left side shows it read-only (`CampaignSummary`). An ended one shows under the same sentence (`CampaignEnded`). Its recipients have no cross and no « Ajouter ». « Arrêter » is in its menu while it carries `stop`, after confirmation.
  - Its status is a badge wherever it appears (`CampaignStatusBadge`). The list is filtered by status in the url (`?status=`, `features/campaigns/status-filter.ts`): « En cours » by default (draft, frozen, started), « Arrêtées ou terminées », « Toutes ».
  - An exchange logged in a campaign shows a « Campagne : … » badge next to its line in the timelines (outside the button that opens its detail, `asideOf` in `TimelineCard`), in the calendar's last exchanges and in its detail (`CampaignOfTheExchange`). The badge links to the campaign when the api provides `_links.campaign`, and reads « Campagne effacée » once the campaign is erased. A processed recipient opens the exchange logged for them in the detail sheet (`OpenTheExchange`). Erasing an exchange reads the campaign, its recipients and the list again once the reactions have run (ADR 0152).
- A contact's or an organization's to-dos are read in full, never in slices (ADR 0113). They show in the « À faire » section of its card when it carries the `toDos` link (`features/to-dos`). « Ajouter », in the section header, or in its middle while nothing is to do, opens a dialog with the revision form: its text focused, shortcuts for its due day (`DUE_SHORTCUTS`), and « Ajouter et en noter une autre », which keeps the dialog open for the next one. Overdue to-dos are red (`isOverdue`, in the browser's time zone), and done ones are folded. Ticking one off offers « Noter l'échange ? », which opens the exchange form with its contact, or with the organization itself, at the moment of the click (`useNoteTheExchangeProposal`).
- A planned exchange's detail (`ExchangePanel`, in its sheet and in the calendar dialog) shows the state of its push to the member's Google calendar (`features/exchanges/components/google-sync.tsx`, ADR 0133). It shows the Google « G » (`shared/ui/google-logo.tsx`) with a check, a clock or a warning, and its reason and time on hover. It offers « Réessayer » once Google has refused it. It shows nothing while the exchange is not pushed to the member's calendar. While its push is pending (no reason), the push's state is read again as an awaited link, five times at most (`googleSyncQuery`). These reads stop once the push is no longer pending, and never run while it waits for the member to reconnect.
  - The video call form offers « Créer un lien Google Meet », checked, while two conditions hold: the connections the app keeps for its banner say Google is connected, and no link is written (`MeetLink` in `plan-form.tsx`, read from their cache; the form never requests them again). While a video call waits for that link (`linkAwaited`), its detail reads it again five times at most, after 1, 2, 4, 8 then 15 seconds. It stops once the link arrives (`exchangeQuery`, `awaited-push.ts`, ADR 0137). There is never steady polling. A gesture on an exchange reads it again once its reactions have run (`readAgainAfterTheReactions`).
  - An exchange imported from Gmail (`importedFrom`) carries the Gmail « M » (`shared/ui/gmail-logo.tsx`) on its channel icon, in every timeline and in its detail. It shows « Importé de Gmail » on hover and for screen readers (a `title`, since the line is the button that opens the detail). Its detail says « Importé de Gmail le … » instead of who logged it, and offers « Ouvrir dans Gmail » in a new tab while the API provides the `openInMailbox` link (ADR 0174).
  - What an AI created through the MCP server (`createdByAnAI`) carries the « MCP » badge (`shared/ui/created-by-an-ai-badge.tsx`). The badge reads « Créé par une IA » on hover and for screen readers. The AI is never named. An exchange shows the badge next to its channel in every timeline and in its detail. An organization shows it under its name (`OrganizationBadges`). A contact shows it in their card's header (ADR 0185).
- A file attached to an exchange goes from the browser to S3 with a form the API signs, then is attached through its upload. It is downloaded through a link that the API returns, signed for one minute. The link shown is the API's (`features/exchanges/attachments.ts`, ADR 0077). A new exchange returns its address in `Location`, so its files can be attached once it is logged.
- Code splitting: one chunk per route (router plugin); MapLibre is loaded with `lazy()` only on pages with a map.

## Navigation

- "Retour" behaves like the browser's back button (`shared/ui/back-button.tsx`). From the dashboard map, it returns to the dashboard. From a filtered list, it returns to that list with its search. When the page was opened from a bookmark, it falls back to a link.
- A resource page is made of sections (`shared/ui/editable-section.tsx`). Each section shows one part of the resource and changes it in place through its own small form (`shared/forms/section-form.tsx`), one API intent per section (ADR 0025). Only creation has a full form. A section is editable (`editable`) only when the resource carries the link for that intent (`organization._links.relocate`). The same holds for an image being changeable (`onUpload`) and for a button being shown. The API decides what is possible (ADR 0027), and the front never re-implements it.
- A creation form is left with `useGoBack` (cancel), and replaces itself with the new page (`replace: true`). The history never holds a form that is already done with.
- The dashboard shows my day above its figures (`features/exchanges/my-day`, composed by the route, as for the calendar):
  - « Aujourd’hui »: what I still have planned today, with the time left before each one (« dans 25 min »). The one in progress is set apart. An exchange whose time has passed shows « À traiter ». When it carries their links, it also shows « Fait », which opens its dialog on the report, and « Manqué ». « Rejoindre » joins a video call, and « Appeler » calls the number its detail gives.
  - « À venir »: the next five (« demain 9h00 », « lundi 14h00 »), and « Voir le calendrier ».
  - An exchange opens in the calendar dialog. When nothing is planned today, the card offers « Planifier » in that day's calendar, if the day carries `searchContacts`.
  - It is read for the browser's day (`myDayQuery`). Its loader starts the read without waiting for it, and its cards suspend on their own (`MyDaySkeleton`), so a slow day leaves the rest of the dashboard visible. It is read again after every gesture on an exchange (`queryKeys.myDay`, alongside the calendar).
- Above them, the dashboard shows « À traiter » while there is something to process (`features/exchanges/to-process`). It first lists what I planned whose end has passed and that I have not handled yet, whatever its day, oldest first. Then it lists my to-dos for today and late ones, « Pour aujourd’hui » or « En retard de 3 jours », ticked off in place (`ToDoLine` in `features/to-dos`, passed in by the route). A tick says « Action faite » in a toast for six seconds. That toast offers « Annuler » while the done to-do carries `untick` (`useTickOffToDo({ undoable })`). « Annuler » unticks the to-do. The toast lives in the mutation's options, so it outlives the line that leaves. A to-do carrying `revise` also offers « Reporter », which opens its revision, where a shortcut sets its new day. It uses `exchangesToProcessQuery`, sent with the browser's time zone (`readerTimeZone()`). The query is read again every five minutes and after every gesture on an exchange or a to-do (`queryKeys.exchangesToProcess`, ADR 0134). As its links allow, each line offers « Fait », which opens its dialog on the report, then « Planifier la suite », « Manqué » and « Annulé », which remove the line immediately while their toast can undo the gesture (`useUndoable`), and « Déplacer », which opens its dialog on the move. « Tout est à jour 🎉 » appears once the last item I processed leaves the card. The menu's « Tableau de bord » entry counts them, exchanges and to-dos (`ToProcessCount`).
- The contacts I hold that need attaching (`features/contacts-to-attach`, ADR 0146) are read with what is to process and counted in its badge. They show as « Contacts à rattacher » in « À traiter » (`ContactsToAttachSection`, passed in by the route to `ExchangesToProcessCard`). Each one is a queue line: a person's tile, its name, its email, its last meeting, and the days left before its erasure in a chip. The chip reads « N jours ». On hover and to a screen reader, it says « Effacé dans N jours ». It is neutral, orange from 7 days and red on the day before. The line shows « Rattacher », a secondary action, when it carries the `proposedOrganization` link (the right to manage personal data). On a phone, the chip sits above « Rattacher », so that the name and the date keep one line each. That button opens a dialog. The dialog proposes the organization matching its email domain, a search among my organizations, or a new organization prefilled from that domain. With `useAttach`, the organization is created, then the contact is added to it, and what the reactions change is read again after them. The page of a contact to attach shows a « Contact à rattacher, effacé le … » banner from its `toAttach`, with « Rattacher » on the same link (`ToAttachBanner`, composed by the route). The erasure reminders (`ErasureReminders`) are mounted by the `_app` layout with my exchange reminders, according to my settings. They show a toast once a week before and once on the day before, across all tabs (`localStorage`). When the browser keeps nothing, they cover the current tab alone. Their « Rattacher » opens the dialog, or the page when there is no link. An exchange whose contact is waiting to be attached shows « À rattacher » in the timeline, the calendar, my day and « À traiter », from its `contactToAttach` (`ToAttachBadge` in `features/exchanges`).
- My exchange reminders (`features/exchanges/reminders`, composed by the `_app` layout with my settings, `/api/me/reminders`) live entirely in the SPA. The server sends nothing, and they work while the application is open.
  - They read my day, today and the next days (`useMyDayToRemind`, with the `myDayQuery` key and its own observer disabled). They read it immediately, then every 5 minutes, in the background too. They also read it once after a gesture changed it, when the page's reads and its reactions are done. They never read it alongside them, which would delay them.
  - They wake up at the time of the next reminder (`schedule.ts`). That time is `minutesBefore` an exchange that is still planned. When the application opens after that time and before the exchange, they wake up immediately. They never wake up once the exchange started more than a minute ago. A moved exchange is a new reminder.
  - A reminder is a toast that stays until it is closed. It shows the exchange's channel, its interlocutor, their organization and its time. It offers « Rejoindre », « Appeler » or « Itinéraire », depending on its channel. It offers « Dans 5 min », which shows it again then. A click opens the exchange on its contact's or its organization's card (`?exchange=<id>`, the detail sheet over the card).
  - The reminders already shown are kept in `localStorage` (`reminded.ts`), which every tab of the browser reads. Tabs learn of a change through its `storage` event. A reminder shows in one tab only: a background tab lets a foreground tab show it first (2 s). In the background, a browser notification (once allowed, `shared/lib/browser-notifications.ts`) brings the member back to the tab and opens the exchange. The tab's title blinks (`shared/lib/blinking-title.ts`) until the tab comes to the foreground.
  - My to-dos for the day are reminded the same way (`ToDoReminders`, `to-do-schedule.ts`, read with what I have to process). A to-do with a time is reminded `minutesBefore` it, and one without a time at 9:00 on its day, or when the application opens later that day. The toast opens its day in the calendar (ADR 0134).
- The dashboard shows the five figures the API counts, as they arrive (`features/dashboard/components/dashboard-figures.tsx`). None is computed in the browser from a list or from the markers, which stop at 1 000. The reactions to a gesture update a figure about a second after it. The gestures that change one (starting, changing, relocating or stopping an organization, collecting or forgetting a contact, logging, correcting or erasing an exchange) read the dashboard again once the reactions have run (`readAgainAfterTheReactions`, `shared/api/reactions.ts`).
- The member's calendar (`/calendar`, « Calendrier » in the main navigation, `features/exchanges/calendar`, ADR 0115):
  - Views: month (the default, an « Agenda » list on a phone), week, day and agenda, with the view and the day in the URL (`?view=&date=`). The grid is the project's own, built on the tokens, with the browser's dates. `dates.ts` makes a period of whole days, sent with each bound's offset. `time-grid.ts` places a day's exchanges side by side when they overlap. Custom properties that the classes read position them: this is the one place where a position is data rather than style.
  - Each period shown is its own query (`calendarQuery`). The next and previous periods are read when their arrow is hovered, and the three days around a day are read ahead. Every gesture on an exchange reads the calendar again (`queryKeys.myCalendar`).
  - An exchange's look follows its status (upcoming in full colour, done faded, missed hatched, cancelled struck through, planned and past « À traiter » in the warning colour). It opens in a dialog (`exchange-dialog.tsx`). The dialog shows its detail and what it offers (`ExchangePanel`, as in its sheet). It shows a short contact summary with their last three exchanges (`ContactSummary` in `features/contacts`, passed in by the route, since a feature never imports another). The summary is read masked: their name and organizations only (ADR 0129). The dialog also offers « Ouvrir la fiche ».
  - An exchange carrying the `move` link (ADR 0119) can be dragged with the pointer. In the week and day views, it goes to another quarter hour or another day. In the month view, it goes to another day at the same time. It can also be stretched by its end (`gestures.ts`, `use-gestures.ts`). Once it is grabbed, the window follows the pointer, and the exchange is redrawn in another column. It shows at its drop position immediately and goes back where it was when the API refuses. Its toast offers to move it back when the response carries the `moveBack` link (ADR 0135: its former time is still to come). Otherwise the toast reports the move without that offer (`useMoveInTheCalendar`). The offer stays however long the member takes. It ends when another exchange is moved or opened (it can be moved from its dialog), or when the member leaves the calendar. There is one toast, which never closes on its own. A slow API answer delays it. A move answered after the member leaves the calendar is reported without the offer.
  - When the calendar carries the `searchContacts` link, clicking a free slot in the week or day view, or dragging over it for its duration, opens planning there (`plan-in-a-slot.tsx`). A contact or an organization is searched as everywhere else (`InterlocutorSearch` in `features/organizations`, passed in by the route). The form is offered when their timeline carries `planExchange`.
  - The keys T, ← →, M S J A drive it, except while typing in a field or when a dialog is over it (`shortcuts.ts`).
  - It shows my to-dos too (ADR 0134), filtered as « Tout », « Échanges » or « À faire ». In the week and day views, a day's to-dos without a time sit in a band above the hours, and those with a time sit at that time, without a duration. In the month and agenda views, they come first in a day. They are shown on the day written, whatever the browser's time zone (`to-dos.ts`). Each is ticked or unticked in place with its box (`ToDoBox` in `features/to-dos`, passed in by the route). Its tick offers « Annuler » for six seconds, as in « À traiter ». Done ones are greyed and struck through. A to-do can be dragged to another day when it carries `revise`, and it keeps its time (`toDoDrop`, a browser drag, with the revision passed in by the route). With the keyboard, it is revised from its card.
  - What the API reports as late (`late`, read with the browser's time zone) shows the `warning` token on its edge, an icon and « En retard », never colour alone. It pulses once when shown, and never under `prefers-reduced-motion` (`animate-late-once`).
- The member's settings (`/settings`, « Configuration » in the user menu, `features/settings`) are made of sections. The URL names the one shown (`?section=`). A computer shows a side navigation, and a phone shows tabs.
  - A setting follows the account, is saved immediately and confirmed by a toast (the reminders, `/api/me/reminders`).
  - The member's booking page (`features/booking`, ADR 0148, 0151) has a switch that opens or closes it. The switch is refused while Google is not connected (a panel leads to the connectors). The seven days' windows, on the quarter hour, are saved together in the browser's time zone. « Copier sur les jours ouvrés » copies the first day to the working days. Inactive periods are added and removed. Channels are saved as they are checked. Its link can be copied, previewed, shown as a QR code drawn in the browser by `qrcode` and downloadable as a PNG, and changed after confirmation.
  - The page the link leads to, `/booking/$code`, is outside the shell and the sign-in guard, and is read without signing in. It shows who the host is and the channels offered. Then it shows the free slots of the next 14 days, on the visitor's clock, with the host's clock named (`features/booking/slots.ts`). A slot is chosen once a channel is. A link that offers nothing says only that no slot is available (ADR 0153). The chosen slot is recalled above the booker's form (`BookingForm`). The form holds the first name, name, phone formatted as typed, e-mail and optional subject, and says what their details are used for. It also holds a trap hidden from people and the time the form was shown, so the API can set robots aside. Once the slot is booked, the page says what comes next: by e-mail, the call to the phone number in international format (`phoneAsRead`), or the video call link. An upcoming appointment is shown with its time. A slot taken in the meantime sends the booker back to the slots, read again (ADR 0164).
  - The shell reads the agenda of the next 16 days every five minutes. It reports in a toast each exchange booked through the member's link that it had not found on its first read (`NewBookings` in `features/exchanges/bookings`). Such an exchange's detail says it was booked through the public link. While the member's open link is suspended, `BookingSuspendedBanner` says so above every page of the shell.
  - The connectors (`features/connectors`, ADR 0120) are checked with their providers each time their section opens (`checkMyConnections`). Its answer is kept as the state that `ReconnectBanner` reads above every page. While Google does not answer (`googleUnreachable`), the connections are read as last seen, marked unchecked, and still disconnected. Google is shown as unavailable, neither connected nor reconnected, while the connections lack their `connectGoogle` link (the account has no Google client). While the connections carry the `googleClient` link, an administrator configures that client below (`GoogleClientCard`, ADR 0125). The card gives the redirect URI to declare in the client. The administrator types its secret, which is never shown again. The Google card counts the member's upcoming exchanges synced and failed there. It offers « Tout réessayer » while one has failed (`retryFailed`, ADR 0133). Google brings the member back to `/settings/connectors/google`. The page sends the code to the API once, then returns to the section with a toast.
  - The theme stays in the user menu, as a device preference.
- Map markers open a quick look (`features/organizations/components/organization-preview.tsx`, rendered by `GeoMap`'s `renderPopup`), which loads the organization into the cache: its page then opens instantly.

## API access

- `pnpm api:types` (or `make api-doc` from the root) regenerates `shared/api/schema.d.ts` from `apps/api/openapi.json`. `api` calls the API with the access token, including the sign-in call (`/api/me/sign-in`).
- `api.queryOptions('get', '/api/organizations/{id}', { params })` / `api.useMutation('patch', ...)`: path, params, body and response are typed. A query's other options go in its fourth argument (`api.queryOptions('get', '/api/me', undefined, { refetchInterval })`), typed by TanStack Query, never spread over it with a hand-written type. A `refetchInterval` that must run while the tab is in the background sets `refetchIntervalInBackground: true`: otherwise TanStack Query refetches only while the window has focus.
- The fetch middleware adds `Authorization: Bearer`. On a 401, it renews the token once with the refresh token. Otherwise, it sends the user to sign in.
- Form values have the shape of the API input (`street` in the address section, `address.street` in the creation form), so each API violation's `propertyPath` is the form field name. Field groups that several forms share live in `shared/forms` (`AddressFields`, `ContactDetailsFields`, `LegalIdentityFields`, `PersonNameFields`, with their zod schema and conversions). Their `path` option nests them in a bigger form.
- A field shows its error through `FormField`, which subscribes to it (`useFormState`): the React Compiler memoizes components that receive the same `form`, so a field group would not render a new error on its own.
- Errors are RFC 9457 problem details (`shared/api/problem.ts`). `refusals` in `fr.ts` words a refusal from its `reason` and `context`. Otherwise the refusal keeps the API's wording (ADR 0073). `applyViolations()` puts the server's validation errors on the form fields. Other mutation errors raise a toast (`query-client.ts`), unless the mutation sets `meta: { silentValidation: true }` and handles 422 and 403 (the role refusal, `roleNotAllowed`) in its form. Such a mutation is called from a form that passes its errors to `applyViolations()`. A gesture without a form (a to-do dropped on another calendar day) leaves its refusals to the toast. A page refused for the role says so in its title. The reason is worded under the title only when it names a right the role lacks (`personalDataManagersOnly`). A gesture whose refusal that toast reports calls `mutate`, and puts what follows its success in the call's `onSuccess`. It never calls `mutateAsync` without catching its rejection: the browser would report an uncaught promise for a refusal already shown (`features/booking`). Known debt: the confirmations on other screens still wait for this (stopping prospecting, forgetting a contact, the campaign gestures, the connectors, erasing an exchange, an organization's contacts).
- Uploads are separate multipart endpoints (`shared/api/upload.ts`).
- An image comes in sizes (`smallUrl` 96 px, `mediumUrl` 256 px, `url` the original). Show the smallest one that covers twice the displayed size (high density screens). Use `smallUrl` for avatars, markers and cards, and `mediumUrl` for an image section.
- Ids are UUIDs. A route param that is not one is a 404 before any request (`shared/lib/route-params.ts`). An API 404 in a loader becomes the same not found page.

## Authentication

See `docs/architecture/auth.md`. In the SPA, `shared/auth/session.ts` signs in on the user pool the API names (`GET /api/user-pool`) and provides the access token, renewed once expired. The `_app` layout route uses it to guard every page. It sends an anonymous visitor to the sign-in screen, `routes/auth/sign-in.tsx` (`features/sign-in`). Once the visitor is signed in, that screen returns to the requested page (ADR 0037, 0052).

Once signed in, a member whose profile has no name completes it before anything else, when the account carries the `changeMyName` and `changeMyContactDetails` links. The `_app` layout loads the account and shows « Complétez votre profil » instead of the shell (`features/account/components/complete-my-profile-form.tsx`). It proposes their login email for their profile. The form sends the profile through the account's intents, the email then the name, each its own use case. Then it opens the home page (ADR 0100). A reaction to their registration creates their profile shortly after it (ADR 0101). Until then, their account is refused as a person not found (`unknownPerson`). The layout shows « Votre profil est en cours de préparation… » (`features/account/components/my-profile-being-prepared.tsx`). It reads the account again after 1, 2, 4, 8, 16 s… until it exists. After a minute of waiting, it shows « Réessayez plus tard » (`nextReadingOfMyProfile`). That screen, and the layout's error when the account cannot be read, offer « Se déconnecter » (`app/layout/sign-out.tsx`), since the user menu is out of reach. The sign-in screen and this one are single-card pages outside the shell (`app/layout/card-page.tsx`).

## Adding a screen

1. If the API changed, `make api-doc`.
2. In `features/<feature>/`: query options, mutations (update the cache), a zod schema mirroring the API input, components.
3. A route file in `routes/_app/...` with a `loader` (`ensureQueryData`), `pendingComponent`, `errorComponent`, and the page component.
4. Texts in `shared/i18n/fr.ts`.
5. A component test for the behaviour (the SPA on its routes when it crosses the router or the layout); a Playwright journey only for what no other test covers (ADR 0122).

## Rules

- Respect the folders: `routes/` thin (loader + page), `features/<feature>/` (queries, mutations, schema, components), `shared/` business-agnostic. A feature never imports another feature. Shared query keys go in `shared/api/keys.ts`. `shared` imports nothing from `app`, `features` or `routes` (Biome's `noRestrictedImports` refuses it).
- Server data goes only through TanStack Query with the generated `api` client (sign-in included: `/api/me/sign-in`). Signing in, renewing the token and signing out go through `shared/auth/session.ts` only (Cognito). Never `fetch` by hand (except to send a private file to S3 with the form the API signed, `features/exchanges/attachments.ts`, ADR 0077), and never copy server data into `useState` or Zustand. Mutations update the cache with the returned resource, then invalidate the affected list prefixes.
- Route data: a `loader` with `context.queryClient.ensureQueryData(...)`, a page with `useSuspenseQuery`, plus `pendingComponent` and `errorComponent`. A page that cannot load at all (the api is unreachable) falls back to the root route's `PageError`. Search state goes in validated search params. A list comes in slices (`useInfiniteQuery`, the `next` link, "Charger plus", ADR 0049), never numbered pages.
- Never write `useMemo`/`useCallback`/`memo` for performance: the React Compiler does it.
- After an API change: `make api-doc` (regenerates `src/shared/api/schema.d.ts`, never edited by hand), then fix the type errors.
- Forms: react-hook-form + a zod schema mirroring the API constraints. Show server violations with `applyViolations`. A resource is changed section by section, one intent each: `EditableSection` + `SectionForm`, shared field groups in `shared/forms`, fields through `FormField` (it subscribes to its own error; the React Compiler would not re-render a memoized group). `Field` gives its label, error and hint to its direct child. So a controlled field puts its `Controller` around the `FormField`, never inside it (`CountryField`). Otherwise the control has no name for screen readers. Only creation has a full form. A form emptied for the next entry is remounted with a new `key` (`AddToDoDialog` for to-dos), never reset in place with `form.reset`. `reset` forgets which fields are mounted until they register again on the next render, and the React Compiler skips that render. The inputs then show values the form no longer reads, even with `keepFieldsRef` from the second reset on. Show an action only when the resource carries its link (`_links.<intention>`), never based on the data itself.
- A change that overwrites a sheet's fields is sent on the record's revision at the moment its form opened (ADR 0187). `SectionForm` keeps its `revision` prop from its first render and gives it to `save`. `save` sends it as the `PATCH`'s `revision` query parameter, never in the body. The exchange's corrections keep it while one is open (`useRevisionWhenOpened` in `exchange-detail.tsx`). A refetch while the member types does not move it. When the API answers 409 `changedMeanwhile`, the form says the record changed and is to be reloaded. A contact's title, sent after the name, goes on the revision the rename answered.
- UI: compose `shared/ui` components and semantic tokens (`bg-card`, `text-muted-foreground`…), with no raw colors and no inline styles. A `style` carries only CSS custom properties, for a position computed from data that the Tailwind classes read (`time-grid-view.tsx`: `--start`, `--length`, `--lane`, `--lanes`, `--now`). Every text that is shown or announced (to screen readers too: `sr-only`, `aria-label`, `title`, `placeholder`, `alt`) goes through `t()` with a key added to `shared/i18n/fr.ts` (keys are typed). `make lint` refuses a text written in the code (`lint/translated-texts.grit`, ADR 0093), but never a thrown error or a log. A library's texts come from `fr.ts` too: MapLibre through its `locale` (`map-view.tsx`), Sonner through `closeButtonAriaLabel` (`shared/ui/sonner.tsx`), a shadcn component through its props. « de » before a name is written `{{name, de}}`. The `de` formatter (`shared/i18n/de.ts`) elides it before a vowel (« d’Anaïs », « de Pauline »), never before an h.
- Labels: `shared/i18n/fr.ts` is one object of sections, one per screen or context (`campaigns`, `exchanges`…). It also has `common` for words every screen uses (« Enregistrer », « Réessayer »), `fields` for contacts', organizations' and members' fields, whichever form shows them, `validation` for form errors, and `refusals` for API refusals. A screen reads its own section and these shared ones, never another screen's section for its words: the day that section changes, the screen would change too. The same text gets its own key. Only the name of the same thing is read from its context (a campaign's channel is its exchanges' channel, `exchanges.channels`). A function that receives `t` types it as i18next's `TFunction`, never `ReturnType<typeof useTranslation>['t']`. That type instantiates the hook with the union of every key prefix. `tsc` stopped typing the keys (TS2589) once there were a few hundred labels. `lint/labels-headroom.test.ts` type checks the front with a hundred extra labels, so that such a limit cannot come back unnoticed.
- Spaces in the labels: a colon follows a no-break space (U+00A0). A semicolon, a question mark or an exclamation mark follows a narrow no-break space (U+202F). French quotation marks hold their text between no-break spaces (« Membre sans nom »). `make lint` refuses a label of `fr.ts` that breaks this (`lint/french-spacing.grit`), and `make fix` puts the right space in. `shared/i18n/fr.test.ts` checks the same rules on the labels themselves.
- Navigation: "Retour" goes back in history (`shared/ui/back-button.tsx`, with a fallback link when the page was opened directly). A creation form is left with `useGoBack` and replaces itself (`replace: true`), so going back never lands on a form already submitted or cancelled.
- Accessibility: every control labelled (`Field`), icons `aria-hidden` next to text, everything reachable by keyboard.
- Style: Biome (single quotes, no semicolons, 110 columns), `import type` for types, the `@/` alias for `src/`.
